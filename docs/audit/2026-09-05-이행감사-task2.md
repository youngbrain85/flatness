## 감사 메모

**1. 세부과업 2에만 요구항목 이행 매핑표가 없다 — 불일치 25건의 대부분이 여기서 나온다.**
보고서는 세부과업 4에 9.2절 "과업지시서 요구사항 대비 이행 현황"을, 세부과업 3에 11.3절 "요구 항목 이행 매핑"을 두었다. 세부과업 2(10장)에는 그런 절이 없고, 10.8절 한계 9건은 **수행한 것의 신뢰 범위**를 다룰 뿐 **요구했으나 하지 않은 것**을 다루지 않는다. 그 결과 비교·선정 구조(T2-05·T2-06·T2-32), 입력·수정·이력 모듈(T2-09·T2-10·T2-34), 마감재 축 시각화(T2-13), 유지관리 우선순위(T2-17·T2-18·T2-38), 안내로봇(T2-03), 내구성·유지관리성 속성(T2-02·T2-22)이 보고서 어디에도 드러나지 않는다. 위 표의 `false` 다수는 적극적 과장이 아니라 **이 구조적 침묵**이다.

**2. 산출물 형식 CSV 결측 — 보고서가 지시서 요구를 축소 인용했다.**
보고서 10.1 표는 "산출물 형식 | 지시서: **—** | 이 과업: IFC + PDF | 구속력: 있음"이라 적고 본문에서 "산출물 형식은 지켰습니다"라고 단언한다. 그러나 과업지시서 6쪽은 세부과업 2의 결과 형식을 `CSV(데이터), JSON(DB 연계정보), PNG(시각자료), PDF(보고서)`로 명시한다. 실제 산출은 JSON·PNG·PDF 3종이고 CSV가 없다. 저장소 기록 규칙("산출물 형식·정밀도는 이탈 대상이 아니다")과 보고서 9.2.1절의 자기 방침("산출물 형식은 구속력 있음, 빠진 산출물은 이탈이 아니라 미이행")을 그대로 적용하면 이것은 **미이행 요소**다. 세부과업 4에서는 같은 논리로 PDF를 나중에 채웠으므로(9.2.1절), 세부과업 2에도 같은 잣대가 적용되어야 한다.

**3. 판정 엔진의 실제 커버리지가 임계값 DB보다 훨씬 좁다(T2-16·T2-37).**
`robot_thresholds` 29행은 12개 지표에 걸쳐 있으나 `bim/judge.py`가 판정에 쓰는 것은 `step_height_mm` 하나다(`judge_class`가 인접마다 단차 하나만 평가하고 그 결과로 BFS 그래프를 만든다). 통과폭·경사·회전폭·카펫 파일·미끄럼저항 임계값은 적재만 되어 있고 어떤 코드도 소비하지 않는다. 보고서 10.5의 "원인은 통과폭이 아니라 단차입니다" 문단은 코드 판정이 아니라 **사람이 수동 대조한 서술**이다. DB 쪽 `fn_eval_group`/`fn_resolve_thresholds`는 다지표 평가가 가능하지만 호출처가 회귀 스크립트 `015`뿐이고, `passability_assessments`/`assessment_findings`는 0행이다.

**4. 확인하지 못한 항목 — 운영 인스턴스 적용과 DB 회귀 게이트.**
보고서 10.6·10.8은 "운영 인스턴스 적용 완료(검증 게이트 PASS 38/38, 2026-08-10)"와 "격리 PostgreSQL 16.14 적재 exit 0", "DB 변이 실험 41종 전부 차단"을 주장한다. **본 감사 환경에는 psql·pg_ctl·docker가 없고 운영 인스턴스 접근 권한도 없어 재현하지 못했다.** 저장소가 증명하는 범위는 `supabase/verification/015_finish_material_regression.sql`이 `generate_series(1,38)`로 단언 38건을 요구하고 실패 시 종료코드 ≠ 0을 내도록 작성돼 있다는 사실까지다. 더구나 보고서·DEPLOY.md·설계 정본이 절차로 지목한 `pgsetup.sh`·`run015.sh`·`tree.sql`·`mktree.py`는 **작업 트리 어디에도 없다**(파일시스템 전수 탐색). 즉 DB 검증과 문서 생성은 저장소만으로 재현 불가다.

**5. 직접 실행해 확인한 것(증거).**
- `python -m pytest bim/tests/ -q` → **50 passed**. 보고서 10.7의 "코드 테스트 50건" 일치.
- 스크래치패드 복사본에서 `to_ifc.py`(입력: `bim/tests/fixtures/lh26_dump.json`) → IFC4 47.0KB, IfcSpace 9(기하 7 / 기하 없음 2=복도·실외기실), IfcDoor 4, IfcMaterial 12. 보고서 10.6 표와 일치.
- 같은 산출물에 `verify_ifc.py` → 길이단위 METRE, 실별 면적 오차 최대 **−0.0025%(현관)**, 나머지 6면 ≤0.0009%, `IfcMaterialLayerSet 0`(전부 두께 미주장), "검증 통과 — 실패 0건", exit 0. 보고서 10.2·10.6.1의 0.003%/0.0025% 주장 일치.
- 저장소 파일은 하나도 만들거나 고치지 않았다(생성물은 전부 스크래치패드).

**6. 판단이 갈릴 수 있는 항목.**
- **T2-25(C# BIM-API)를 '의도적 이탈'로 둔 근거**: 저장소 기록 규칙상 언어·라이브러리는 자유이고 보고서가 사유를 적었다. 다만 "BIM-API"는 단순한 도구 선택이 아니라 **원본 BIM 모델의 존재를 전제하는 작업 방식**이므로, 발주 관점에서는 "모델을 확보하지 못해 대체 접근을 했다"는 **전제 미충족**으로 읽힐 여지가 있다. 그 여파를 T2-29(운영 구조)에 '부분'으로 분리 기록했다.
- **T2-11·T2-34(조회/입력 모듈)**: RLS 정책과 PostgREST를 "기능"으로 인정하면 '완료'에 가깝고, 사용자가 조작하는 모듈을 요구로 읽으면 '미이행'에 가깝다. 지시서 문구가 "기능 구현"·"기능 모듈"이고 세부과업 1이 같은 요구를 대시보드 화면으로 이행한 선례가 있어 **'부분'**으로 잡았다.
- **T2-13 vs T2-35**: 색상 시각화 기능 자체는 존재하나 축이 마감재가 아니라 로봇 판정이다. 기능 요구(T2-13)는 '미이행', 성과물 요구(T2-35)는 다른 시각화 결과물이 실재하므로 '부분'으로 갈랐다.
- **T2-07의 '구역'**: 지시서는 "공간, 바닥, **구역** 객체"를 열거하나 대상이 단위세대 1개라 구역 축을 별도로 두지 않은 것이 부적절하다고 보기 어려워 '완료'로 두고 비고에 남겼다.

**7. 경계가 모호한 문장.**
- 과업지시서 12쪽 "추진 일정 — 세부과업 2-3" 항목들은 내용이 전부 Point Cloud 스캔·전처리·BIM-API 연동으로 적혀 있어 세부과업 2의 마감재 DB 일정이 사실상 빠져 있다. 본 감사 범위(4~7쪽) 밖이라 표에 넣지 않았으나, 일정표와 과업 범위가 어긋난 원문 사안으로 기록한다.
- 과업지시서 5쪽 "○ 스마트 빌딩 연계형 분석 기능 개발"의 바닥 상태·평활도 항목(T2-14~T2-15)은 세부과업 1·4(점군 실측)와 경계가 겹친다. 보고서 10.4가 "세부과업 2는 설계 단계 평가, 세부과업 1·4는 시공 후 검증"으로 나눈 해석 자체는 합리적이나, 지시서는 세부과업 2 안에서 **연계 기능**을 요구하므로 연계 미구현은 세부과업 2의 미충족으로 계상했다.
