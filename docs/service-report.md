# 용역 결과 보고서

## 수직·수평면 평활도 분석 결과 자동 보고서 생성 기능 개발 (세부과업 1)

- 제출 문서 구분: 과업지시서 세부과업 1 최종 성과물 "라. 용역 결과 보고서"
- 작성일: 2026-07-31
- 관련 성과물 문서: [`scan-guideline.md`](scan-guideline.md) (현장 스캔 가이드라인),
  [`criteria-sources.md`](criteria-sources.md) (판정 기준 원문 대조표),
  [`contracts/stats-schema.md`](contracts/stats-schema.md) (데이터 계약 정본)

> **본 보고서의 작성 원칙**: 수행하지 않은 검증을 수행했다고 기재하지 않는다. 인용한 수치는
> 전부 본 보고서 작성 시점에 실제로 실행해 확인했으며, 미수행 항목은 6장에 명시했다.
> 특히 **실물 직선자를 이용한 현장 실측 대조는 수행되지 않았다**(6.2절).

## 1. 과업 개요

### 1.1 목적

모바일 LiDAR(iPhone/iPad)로 스캔한 현장 바닥면·벽면 포인트클라우드를 업로드하면, 국내 시방서
기준으로 평활도를 분석·판정하고, 결과를 온라인 DB에 축적하며, 수직·수평면 통합 PDF 보고서를
자동 생성하는 시스템을 개발한다.

기존 방식(Colab 노트북 수동 실행)의 한계를 해소하는 것이 재설계의 동기였다.

| 기존 방식의 문제 | 본 시스템의 해소 방식 |
|---|---|
| Colab 세션 종속. 결과가 세션과 함께 소멸, 이력·공유·비교 불가 | 온라인 DB에 영속 저장, 현장·측정위치 체계로 조회 |
| 단일 전역 RANSAC 평면. 다중 방·단차·설계 구배에서 오판, 벽면 미지원 | 구역 분할 후 구역별 평면 재피팅, 벽면 파이프라인 신설 |
| 판정 기준 근거 부재(임의 임계값 9mm 슬라이더) | 국내 시방서 기준 11종 탑재, 적용 기준을 분석 결과에 박제 |
| 포인트별 Python 루프, 무작위 샘플링 시각화로 결함 누락 가능 | 서브셀 충분통계량 누적, 전 라인 스윕으로 결함 누락 방지 |
| 메타데이터·연계·보고서 없음, 실제 LiDAR 포맷 미지원 | 메타데이터·사진 연계·자동 PDF 보고서, 7종 포맷 지원 |

### 1.2 범위

**포함**
- 바닥면(수평)·벽면(수직) 평활도 분석 및 4등급 판정
- 온라인 대시보드 (업로드, 현장·측정위치 관리, 결과 조회, 사진 연계)
- 온라인 DB (Supabase Postgres) 및 파일 저장소
- 수직·수평 통합 PDF 보고서 자동 생성 (자동 종합의견 + 사용자 수정)
- 판정 기준 관리 (전역 기본값 + 현장별 재정의)
- 기존 분석 프로그램 결과 데이터 임포트 (Colab 노트북 CSV + 범용 JSON `flatness-import-v1`)

**제외** (설계 정본 §2.2에서 명시적으로 제외를 결정한 항목)
- 과업지시서 세부과업 2~4 (마감재 DB, BIM-API 연계, 구배 알고리즘). 단, 데이터 포맷·산출물
  형식은 향후 연계가 가능하도록 유지 (7장 참고)
- E57 파서 (현재 사용 장비가 내보내지 않는 TLS 중심 포맷. 파서 인터페이스만 추상화)
- 모바일 전용 앱, 실시간 스캔 스트리밍, 다중 조직 권한 체계, 계단 분석
- 벽면 단차(step) 지표. 지표는 flatness/plumbness 2종으로 한정

**결과표의 실제 컬럼**(`report.html.j2` §3 라인 대조):

| 섹션 | 컬럼 |
|---|---|
| 3.1 수평면(바닥) | 구간 · 상태 · 레벨(m) · 면적(m²) · 셀(유효/전체) · 최대(mm) · 최소(mm) · 평균(mm) · 기준 초과 셀(비율) |
| 3.2 수직면(벽면) | 구간 · 길이 x 높이(m) · 수직도(mm) · 수직도 판정 · 셀(유효/전체) · 최대(mm) · 최소(mm) · 평균(mm) · 기준 초과 셀(비율) |

여기서 "구간"은 바닥은 **구역(zone)**, 벽면은 **벽(wall)** 단위다. "기준 초과"는 보수 + 재시공
셀을 뜻하며 경계는 포함하지 않는다(템플릿에 각주로 명시됨). **셀 단위 상세**(셀 인덱스·중심
좌표·편차값·사용 스팬·등급·최대 결함 지점 좌표)는 보고서 결과표가 아니라 산출물
`results.csv`·`cells.json`과 대시보드 결과 화면의 셀 상세 패널로 제공한다
([`contracts/stats-schema.md`](contracts/stats-schema.md) §6).

**② 가. "돌출·함몰 편차 산정"에 대한 설명**: 본 시스템의 판정값은 실물 3m 직선자를 그대로
시뮬레이션한 값이라 **상부 볼록 포락선 아래 최대 틈새**다. 이 값은 정의상 0 이상인 단일
스칼라이며, 실물 직선자로 재는 값과 마찬가지로 돌출량과 함몰량이 하나의 수치로 합쳐진다.
돌출·함몰의 **구분과 분포**는 부호를 보존한 **정밀 편차맵**(10cm 격자, 0mm 중심 대칭 발산
색상)이 담당하며, 벽면은 `+w` = 실내 방향 돌출 / `-w` = 함몰, 바닥은 `+` = 융기 / `-` = 침하가
코드 상수·범례·테스트로 고정되어 있다. 즉 **요구 항목은 "판정값 + 부호 있는 편차맵" 두 산출물의
조합으로 이행**되며, 판정값 하나만 놓고 보면 부호가 없는 것이 설계 의도다.

**② 다. 3구간과 4등급의 대응**:

| 과업지시서 구간 | 본 시스템 등급 | 판정식 |
|---|---|---|
| 적합 구간 | **적합** | 지표 <= `b1` |
| (해당 구간 없음 - 본 시스템이 신설) | **경계** (현장 재확인 필요) | `b1` < 지표 <= `b2` |
| 보수 구간 | **보수** | `b2` < 지표 <= `re` |
| 재시공 검토 구간 | **재시공** | 지표 > `re` |

"경계"는 측정 불확도 U 때문에 합격/불합격을 단정할 수 없는 구간을 정직하게 분리한 것으로,
**시방서에도 과업지시서에도 없는 본 시스템의 해석**이다(4.1절,

### 2.5 이행 현황 요약

아래 숫자는 **과업지시서 원문 항목 수가 아니라 위 2.1~2.4 표의 세분 행 수**다. 원문 한 항목을
산출물 단위로 여러 행으로 나눠 적었기 때문이며, `(추가 지원)`으로 표기한 요구 항목 외 행은
집계에서 제외했다. 괄호 안이 과업지시서 원문의 항목 수다.

| 구분 | 원문 항목 수 | 세분 행 (완료) | 부분 | 미이행 |
|---|---|---|---|---|
| 가. 분석 결과 연계 성과물 | 3 | 9 | 0 | 0 |
| 나. 자동 보고서 생성 성과물 | 3 | 6 | 0 | 0 |
| 다. 보고서 관리 성과물 | 3 | 4 | 0 | 0 |
| 기술 요구사항 | - | 18 | 0 | 0 |
| 라. 용역 결과 보고서 | 1 | 본 문서 | - | - |

**요구 항목 기준 미이행 0건, 부분 이행 0건**이다. 직전 판까지 부분 이행으로 남아 있던 범용
JSON 임포트 파서는 구현이 완료되어(2.1·2.4절) 부분 이행 항목이 없다.

> 다만 "미이행 0건"은 **과업지시서 요구 항목** 기준이다. 설계 정본이 계획했으나 구현되지 않은
> 항목은 6.5절에 따로 열거했고, 검증 측면의 미수행 항목은 5.6절에 있다. 특히 **실물 직선자
> 실측 대조와 시방서 원문 대조는 수행되지 않았다.**

### 3.4 잡 큐 설계

동시성·장애 복구를 DB와 워커 양쪽에서 처리한다.

- **클레임 (DB 보장)**: `FOR UPDATE SKIP LOCKED` 단일 트랜잭션 (`fn_job_claim`) - 워커가 여러
  개여도 같은 잡이 이중 실행되지 않는다
- **중복 방지 (DB 보장)**: `COALESCE(payload->>'analysis_id', payload->>'scan_id', payload->>'report_id')`
  기준 부분 유니크 인덱스 (status가 queued/processing인 행만)
- **재시도**: 최대 3회, `run_after` 백오프
- **고착 회수**: `fn_reap_stuck_jobs`가 30분 초과 processing 잡을 queued로 되돌리고
  analyses·scans·reports의 상태를 동반 복구
- **동시 실행 없음 (워커 구조에서 나옴, DB 보장 아님)**: `fn_job_claim`은 **잡 타입과 무관하게**
  `created_at` 순으로 1건만 클레임한다. 분석 잡과 보고서 잡이 동시에 돌지 않는 것은 워커의
  `run_loop`가 단일 프로세스로 한 번에 1건만 처리하기 때문이며, **워커를 2개 이상 띄우면 이
  성질은 보장되지 않는다**(데모 구성은 단일 워커). 설계 정본 §3.1의 "잡 type별 직렬 실행"은
  이 단일 워커 전제에서 성립하는 서술이다
- **전송 오류 복원력 (본 갱신에서 반영)**: Supabase가 유휴 keep-alive 연결을 끊은 뒤 워커가 그
  연결을 재사용하면 `httpx.RemoteProtocolError`가 발생해 **워커 프로세스가 죽던 문제**가
  있었다(시연 중 실측). 두 층으로 해소했다. ① 폴링 루프의 `claim_job` 전송 오류는 지수
  백오프(최대 60초)로 재시도하며 복구 시 간격을 원복한다 ② 잡 큐 4종
  (`claim_job`/`complete_job`/`fail_job`/`reap_stuck_jobs`)에 짧은 재시도를 공통 적용해,
  수 분 걸리는 분석 도중 연결이 끊겨 `complete_job`이 실패하면서 **성공한 분석이 실패로
  기록되던** 경로를 좁혔다. `DBError`(HTTP 4xx/5xx, 인증 실패 등)는 재시도해도 무의미한 영구
  오류이므로 한국어 사유를 남기고 그대로 종료한다`[구현: worker/flatworker/runner.py, db.py]`

## 4. 주요 기능별 구현 내용

### 4.1 판정 알고리즘의 원리

핵심은 **실물 3m 직선자 검사를 그대로 시뮬레이션하는 것**이다.

**(1) 서브셀 대표높이** - 5cm x 5cm 격자마다 점들의 **중앙값**을 대표 높이로 삼는다. 점 단위
노이즈 극값이 판정을 지배하지 않게 하는 장치다. 점이 3개 미만인 서브셀은 신뢰도 부족으로 버린다.

**(2) 직선자 포락선** - 실물 직선자는 표면의 **고점에 얹혀** 지지되므로, 기준선은 프로파일의
**상부 볼록 껍질**(monotone chain)이다. 그 아래 최대 틈새가 그 라인의 측정값이다.

> 최소제곱 평면 방식을 쓰지 않은 이유: LSQ 평면은 데이터 중앙을 관통하므로 파형 결함을 약
> 1/2로 축소해 읽는다. 실물 직선자와 다른 값이 나오므로 설계 정본 §5.1.6이 판정 사용을 금지했다.

**(3) 전 라인 스윕** - 판정 셀(1m x 1m)마다 4방향(0/45/90/135도)에 대해 **셀 블록을 지나는
모든 서브셀 라인**을 평가한다. 셀 중심 라인만 검사하면 라인에서 벗어난 결함이 감쇠 측정되어
±1mm 정확도 요구를 위반함이 구현 검증에서 확인되어 개정된 설계다. 셀 값은 환산 허용치 대비
최악 라인의 값이다.

**(4) 4등급 판정** - `s = span_used/span`, `pe = pass x s`, `re = rework x s`, `U_eff = U x s`,
`b1 = pe - U_eff`, `b2 = min(pe + U_eff, re)`로 적합/경계/보수/재시공을 나눈다.
**이 4등급 체계와 불확도 반영은 시방서에 없는 본 시스템의 해석이다**
([`criteria-sources.md`](criteria-sources.md) 5장에 상세히 기술).

### 4.2 구역 분할 (다중 방·단차·설계 구배 대응)

기존 노트북의 가장 큰 결함이 단일 전역 RANSAC 평면이었다. 결함 구역이 RANSAC 인라이어에서
빠져 **측정 자체에서 제외되는 선택 편향**이 발생한다.

본 시스템은 구역(연결요소)을 바닥의 실체로 다룬다.

1. 서브셀 높이 히스토그램으로 레벨 밴드 검출
2. 밴드별 연결요소 분석으로 방·구역 분리 (1m² 미만 파편은 배제)
3. **평면 추종 영역 성장**: 구역별 평면을 피팅한 뒤 인접 링을 평면 기준 ±5cm로 흡수. 고정
   높이 밴드만 쓰면 경사 슬래브에서 커버리지가 붕괴하는 문제(실측: 경사 1.0%에서 100%,
   1.7%에서 68.3%, 2.5%에서 45.8%)를 해소한 개정이다
4. 구역별로 평면을 재피팅해 잔차를 산출. **평면 제거 후의 국부 요철만 판정 대상**이며, 전역
   기울기는 별도 지표로 분리한다

**자동 제외 규칙**
- 주 바닥면보다 0.3m 이상 높고 면적 3m² 이하 -> `furniture`(가구 상판)로 판정 제외
- 서브셀 높이 분포의 쌍봉성(간극 8mm 초과)이 구역의 20%를 넘으면 -> `ghost`(SLAM 유령층)로
  제외하고 재스캔 권고

### 4.3 벽면 처리

바닥과 같은 체계를 벽면 좌표계로 옮긴 구조다.

1. **벽 검출**: xy 컬럼별 z 최소/최대/점수를 누적해 높이 0.8m 이상인 컬럼을 벽 후보로 삼고,
   2D 라인 RANSAC을 반복해 최대 8개의 벽 라인을 추출
2. **팬텀 벽 차단**: 바닥과 천장만 찍히고 중간 높이가 빈 컬럼은 벽으로 인정하지 않는다
   (`cnt_mid` 조건). 천장 포함 스캔에서 허상 벽이 검출되던 문제를 근본 해소한 개정이다
3. **투영**: 벽 평면 ±10cm 내 점을 (u, v, w) 좌표로 변환. 바닥·천장 접합부 각 10cm는 제외한다
   (실물 벽 검측과 동일)
4. **부호 규약**: +w = 실내 방향 돌출. 실내 판별은 밴드 밖 점 질량 비교로 결정한다
   (bbox 중심 휴리스틱은 중심 통과 벽에서 결정적으로 실패해 폐기)
5. **판정 분리**: 셀 판정 = 평면 제거 후 국부 요철 / 수직도 = 전역 기울기(`|b| x 높이`).
   바닥의 레벨 분리와 동일한 원칙이다
6. **벽별 오류 격리**: 한 벽의 투영·피팅 실패가 전체 분석을 중단시키지 않는다. 실패한 벽만
   `wall_{n}_skipped` 경고와 함께 건너뛰고 성한 벽의 결과는 보존한다

### 4.4 보고서 자동 생성

**재현성이 설계의 중심**이다. 발행된 보고서는 원본 분석이 수정·삭제되어도 동일하게 재현되어야
한다.

1. `reports` + `report_analyses` + `analyses` + `scans` + `locations` + `sites` + `photos`를 로드하고
   사전 검증(완료되지 않은 분석·다른 측정위치의 분석은 사용자가 조치할 수 있는 한국어 사유로 거부)
2. 히트맵·3D 프리뷰·편차맵·사진을 `reports/{id}/assets/`로 **복사**하고 히스토그램을 생성
3. `reports.snapshot`(`report-snapshot-v1`)에 수치·기준·**등급 라벨과 색상 팔레트까지** 박제
4. Jinja2 HTML -> Playwright Chromium -> PDF
5. 발행(finalized) 후에는 DB 트리거가 snapshot·pdf_path 수정을 차단

자동 종합의견은 규칙 템플릿이다(LLM 미사용). 판정 분포, 최대 편차 위치, 경고 코드별 해설,
최악 등급에 따른 권고, **스크리닝 한계 고지 문구**를 조합한다. 사용자가 수정할 수 있으며
수정본도 snapshot에 박제된다.

### 4.5 정밀 편차맵

판정 히트맵은 1m 셀 단위 5색 이산 표시라 **결함의 실제 모양과 크기가 보이지 않는다.** 30cm
함몰이든 90cm 완만한 처짐이든 같은 색 사각형 하나로 뭉개진다.

정밀 편차맵은 판정에 이미 사용한 5cm 잔차 배열을 **2x2 평균 풀링**해 10cm 격자로 만들고
연속 색상(0mm 중심 대칭 발산 colormap)으로 칠한다. 점군을 다시 읽지도, 평면을 다시 피팅하지도
않으므로 추가 비용이 거의 없다.

**판정 무관성이 핵심 제약이다.** 이 기능은 판정 파이프라인에 어떤 입력도 제공하지 않고 어떤
출력도 바꾸지 않는다. 편차맵 생성이 실패해도 등급 결과는 동일하다. UI와 보고서 캡션에
"판정 등급 산출에는 사용되지 않으며, 등급은 1m 판정 셀 기준"을 항상 표시한다.

### 4.6 대시보드 사용성 개선 (최종 갱신분)

기능 범위를 넓힌 것이 아니라 **기존 기능에 도달하지 못하던 경로를 메운 변경**이다.

- **업로드 진입 승격**: 상단 내비게이션에 업로드 버튼을 두어 현장 상세 화면을 거치지 않아도
  업로드를 시작할 수 있게 했다
- **빈 상태 온보딩**: 현장·측정위치가 하나도 없는 초기 상태에서 홈 화면과 업로드 화면이 다음에
  할 일(현장 생성 -> 측정위치 생성 -> 업로드)을 안내한다. 이전에는 빈 목록만 보였다
- **재분석 버튼 신설**: 엔진 개선이나 판정 기준 변경 후 기존 스캔을 다시 돌릴 방법이 없었다
  (analyses 행은 업로드 시에만 생성됐다). 스캔 상세에서 같은 표면·기준으로 새 분석을 걸 수 있다.
  **임포트 결과 스캔은 `analyze`가 아니라 `import` 잡으로 분기한다** - 임포트 원본 CSV/JSON을
  일반 포인트클라우드 리더로 잘못 읽으면 편차 컬럼(`Signed_Distance_mm`)이 통째로 무시되어
  결함이 사라진 채 전 셀이 "적합"으로 재판정되고, 그 오답이 현재 분석으로 승격되어 **흔적 없이
  조용히 틀리는** 문제가 있었다`[구현: dashboard/components/reanalyze-button.tsx]`

8m x 6m 합성 평탄 바닥 중앙에 **12mm 함몰**을 주입하고 노이즈 없이 분석한 결과
`[실행 확인]`:

| 항목 | 값 |
|---|---|
| 주입한 결함 깊이 (정답) | 12.00 mm |
| 측정된 최대 편차 | **11.48 mm** (함몰 반경 0.3m) / **11.81 mm** (반경 0.5m) |

> 얹혀 실제 높이보다 작게 읽힌다(실물 직선자도 동일). ±1mm 정밀 게이트는 함몰·단차 픽스처로
> 검증하고, 볼록 픽스처는 포락선 해석값 기준으로 단언한다.

설계 정본 §5.2의 제약은 **3천만 점을 5분 이내, 피크 메모리 증가 2GiB 이내**다.

30,000,000점 binary PLY(30m x 20m, 점 간격 약 4.5mm)를 생성해 `analyze_floor`를 실행한 결과

### 5.4 노이즈 민감도 실측 (가장 중요한 검증 결과)

**본 시스템의 판정 정확도는 스캔 품질에 지배된다.** 결함이 전혀 없는 완전 평탄면에 노이즈만
주입한 실측 결과다`[실행 확인, 기준 floor-kcs-exposed 3m/7mm, U=5mm, 48셀]`.

| 주입 노이즈 (표준편차) | 측정 최대 편차 | 측정 평균 편차 | 판정 (적합/경계/보수/재시공) |
|---|---|---|---|
| 0 mm | 0.00 mm | 0.00 mm | 48 / 0 / 0 / 0 |
| 0.5 mm | 1.52 mm | 1.35 mm | 48 / 0 / 0 / 0 |
| **1.0 mm** | 3.04 mm | 2.71 mm | **0 / 48 / 0 / 0** |
| 2.0 mm | 6.07 mm | 5.41 mm | 0 / 48 / 0 / 0 |
| 3.0 mm | 9.11 mm | 8.11 mm | 0 / 48 / 0 / 0 |

- 측정 편차는 노이즈 표준편차의 **약 3.0배로 일정하게** 나타난다(네 행 모두 배율 3.03~3.04)
- **노이즈 1mm에서 이미 결함 없는 평면 전체가 "경계"가 된다**
- 원인은 구조적이다: 직선자 포락선이 **최대** 틈새를 취하므로 무작위 노이즈가 상쇄되지 않고
  그대로 편차로 계상된다

12mm 함몰을 넣은 경우도 같은 현상이 확인된다`[실행 확인]`.

| 조건 | 측정 최대 편차 | 판정 (적합/경계/보수/재시공) |
|---|---|---|
| 노이즈 0 | 11.48 mm | 36 / 12 / 0 / 0 |
| 노이즈 표준편차 2mm | 15.47 mm | 0 / 44 / 4 / 0 |

노이즈는 결함을 가리는 것이 아니라 **없는 결함을 만들어낸다.** 결함이 없는 44개 셀이 경계·보수로
오염되고 최대값도 부풀었다. 위 판정 분포(36/12 및 0/44/4)는 백로그 티켓 35의 기록과 정확히
일치함을 재현으로 확인했다.

**이 결과의 함의**: 실제 모바일 LiDAR의 노이즈 수준이 2mm 근방이라면, 본 시스템은 평탄한 바닥도
전 구간 "경계"로 판정한다. 이는 오작동이 아니라 **측정 불확도를 정직하게 반영한 결과**이지만,
실용성 측면에서는 스캔 품질 개선 또는 U 재설정이 필요함을 뜻한다(6.3절).

### 5.5 판정 기준 데이터 정합성 검증

`[실행 확인]` 엔진 시드(`seed_criteria.json`) 11행과 DB 시드(마이그레이션 002) 11행이 표면·출처
문자열·metric·span·pass·rework 전 필드에서 완전히 일치함을 확인했다. 전 11건이
`rework = pass x 3` 관계를 만족한다.

동시에 다음 문제를 발견해 [`criteria-sources.md`](criteria-sources.md) 6장에 기록했다.

- 기본 U에서 적합 상한 `b1 = pass - U`가 **0 이하**가 되어 완전 평탄면조차 "적합" 판정이
  원리적으로 불가능한 기준 **3종** (`wall-kcs-tilt-exposed` -2.0mm, `wall-plaster-surface`
  -5.0mm, `wall-plaster-base` -2.0mm). **벽면 평활도 기준 4종 중 3종**이며, 정상인 1종
  (`wall-kcs-tilt-other`)조차 여유가 1mm뿐이다
- `wall-plaster-surface`는 `pass + U >= rework`라 보수 구간이 소멸하고
  `uncertainty_swallows_repair` 경고가 상시 발생
- 설계 정본 §4.1이 기록한 `wall-kcs-plumb`의 "노출 모서리 13mm" 변형이 엔진·DB 시드 어디에도
  없다(조건별 행 분리 규정의 누락)

**조치(본 갱신에서 반영)**: 첫 번째 항목은 이전까지 화면·보고서 어디에도 드러나지 않아 사용자가
"왜 적합이 하나도 없는지" 알 수 없었다. 신규 경고 코드 **`uncertainty_swallows_pass`** 를
추가해 `b1 <= 0`인 기준/불확도 조합에서 자동으로 경고와 한국어 해설이 붙도록 했다
`[구현: engine/flatness/criteria.py]`. **다만 이는 가시화이지 해소가 아니다** - 근본 해소는 U를
실측 재현성으로 갱신하는 것이며(6.3절, 미수행), 백로그 티켓 47로 관리한다. 세 번째 항목은
시드 행 추가만으로 끝나지 않아(수직도 기준이 `core/walls.py`에 고정 조회됨) 티켓 46으로
분리했다.

## 6. 한계와 후속 과제

### 6.1 iPhone LiDAR 스크리닝 도구로서의 근본적 한계

**본 시스템은 합격/불합격을 확정하는 공식 검측 도구가 아니다.** 이는 구현의 미비가 아니라
장비 특성에서 오는 원리적 한계이며, 설계 초기부터 명시적으로 포지셔닝한 사항이다.

학술 문헌 조사에 따르면 iPhone LiDAR 점군의 상대 거리 오차는 방 규모에서 약 3cm(수직 방향은
±7mm 수준), SLAM 드리프트는 이동거리의 1~2%다. **시방서 허용오차(3m당 3~10mm)와 같은
자릿수이거나 이를 초과한다.**

따라서 본 시스템은 다음을 강제한다.

- 판정을 4등급으로 나누고 불확도 구간을 **"경계(현장 재확인 필요)"** 로 분리
- 모든 결과·보고서에 측정 불확도 수치와 **"본 결과는 스크리닝이며 공식 검측(실물 직선자·레벨
  측량)을 대체하지 않습니다"** 문구를 자동 포함
- 판정 불가 셀에 수치를 강제로 산출하지 않고 "판정 불가"로 명시 출력

**실무 활용 방식**: 전수 스크리닝으로 의심 구간을 좁힌 뒤, 그 구간만 실물 직선자로 정밀
검측하는 2단계 운용이 본 시스템이 의도한 사용법이다.

### 6.2 실측 대조 미수행 (가장 중요한 미완 항목)

**실제 현장에서 실물 3m 직선자로 측정한 값과 본 시스템의 판정값을 대조하는 검증이 수행되지
않았다.** 설계 정본 §10.4가 이를 릴리스 게이트로 규정했으나 충족하지 못했다.

- **미수행 사유**: 실제 시공 현장 접근과 검측 장비(3m 직선자·레벨)가 필요하며, 본 개발 범위
  내에서 확보되지 않았다
- **영향**: 5.2절의 정확도 실측은 **합성 데이터**에 대한 것이다. 합성 데이터는 노이즈 모델이
  가우시안이고 공간적으로 무상관이지만, 실제 LiDAR 노이즈는 그렇지 않을 수 있다. 따라서
  **실제 현장에서의 정확도는 알려져 있지 않다**
- **필요 조치**: 현장 1곳 이상에서 동일 구간을 실물 직선자로 측정하고 셀 단위로 대조해 상관을
  보고해야 한다. 이 대조 없이는 본 시스템의 판정값을 공식 검측 근거로 사용할 수 없다

### 6.3 노이즈 민감도 (백로그 티켓 35)

5.4절의 실측대로 **스캔 노이즈가 판정을 지배한다.** 노이즈 표준편차 2mm(실제 모바일 LiDAR
수준으로 추정)에서 평탄면이 전 구간 경계로 판정된다.

구조적 원인: 직선자 포락선이 최악값을 취하므로 랜덤 노이즈가 그대로 편차로 계상된다.

**대응 후보** (어느 것도 아직 채택·구현되지 않음)
1. 서브셀 집계 강화 (중앙값 창 확대)
2. 포락선에 강건 백분위 적용 (최대값 대신 상위 백분위)
3. **U를 실측 재현성으로 재설정** (설계 정본 §4.2가 예정한 작업)

3번이 가장 원칙적이나 6.2절의 실측이 선행되어야 한다. 1·2번은 실물 직선자와의 등가성을 훼손할
수 있어(실물 직선자도 최악값을 본다) 신중한 검토가 필요하다.

### 6.4 판정 기준의 검증 상태

[`criteria-sources.md`](criteria-sources.md)에 상세히 기록했으며 요지는 다음과 같다.

- **시방서 원문을 직접 열람해 대조한 기준은 0건이다.** 전 11건이 2차 출처 교차검증 수준이며,
  그중 5건은 조항 번호·표 번호·현행 승계 여부까지 미확정이다
- 판정식의 4등급·측정 불확도·축소 스팬 환산·재시공 임계는 **시방서에 없는 본 시스템의 해석**이다
- 측정 불확도 U(바닥 5mm, 벽 8mm)는 **실측 근거가 없는 잠정치**다
- 기본 U에서 적합 판정이 원리적으로 불가능한 기준이 3종 존재한다

**발주처 제출물·논문에 기준 수치를 인용하기 전 원문 대조가 필수다.**

## 7. 활용 방안과 세부과업 2 연계

### 7.1 현장 활용 시나리오

1. **시공 중 전수 스크리닝** - 마감 전 바닥·벽면을 LiDAR로 전수 스캔해 의심 구간을 조기 발견한다.
   실물 직선자로 전수 검사하는 것보다 훨씬 빠르며, 본 시스템의 강점이 가장 잘 드러나는 용도다
2. **검측 대상 구간 선별** - 스크리닝 결과 "보수"·"재시공"으로 나온 구간만 실물 직선자로 정밀
   검측한다. 6.1절의 2단계 운용이다
3. **시공 이력 축적** - 현장·동·층·공간·측정위치 체계로 결과가 누적되어 시공사·공정별 품질
   경향을 비교할 수 있다
4. **보수 물량 산정** - 셀 단위 판정과 결함 위치 좌표로 보수 면적을 **산정할 수 있다.**
   단 **자동 면적 집계는 구현되어 있지 않다**(6.5절, 설계 정본 §5.1.7). 현재는 등급별 셀 수와
   구역 면적(`zones[].area_m2`)에서 사용자가 환산해야 한다. 정밀 편차맵은 "어디를 얼마나 갈아야
   하는가"를 평면 도면처럼 보여준다

### 7.2 세부과업 2(마감재 DB) 연계 구조

세부과업 2는 본 과업의 범위 밖이지만, **평활도 판정 결과가 마감재 선정의 입력이 되도록**
데이터 구조를 준비해 두었다.

**연계의 논리**: 마감재는 바탕면 상태에 따라 시공 가능 여부와 필요 두께가 달라진다. 얇은
마감(제물치장·도장·벽지)은 평탄한 바탕을 요구하고, 두꺼운 마감은 요철을 흡수한다. 본 시스템의
판정 기준 자체가 이미 이 관계를 반영하고 있다.

| 본 시스템의 기준 | 대응하는 마감 조건 |
|---|---|
| `floor-kcs-exposed` (3m/7mm) | 제물치장·얇은 마감 |
| `floor-kcs-finish7plus` (1m/10mm) | 마감두께 7mm 이상 |
| `floor-lh-exposed` (3m/6mm) | 제물치장·도장·벽지 바탕 |
| `floor-lh-thick` (3m/10mm) | 마감두께 13mm 초과 |

**즉 판정 기준과 마감재 종류가 이미 1:1로 대응한다.** 세부과업 2는 이 대응을 역방향으로 쓰면
된다: 측정된 바닥 상태로부터 **시공 가능한 마감재 목록**을 역산하는 구조다.

**연계 지점으로 사용 가능한 데이터**

| 데이터 | 위치 | 마감재 DB에서의 용도 |
|---|---|---|
| 측정위치별 종합 판정 | `analyses.overall_verdict` | 해당 공간의 "바닥 상태 등급" |
| 등급별 셀 수·비율 | `analyses.stats.grade_counts` / `grade_pct` | 부분 보수 후 시공 가능 여부 판단 |
| 최대·평균·95백분위 편차 | `analyses.stats.value_*` | **어느 두께의 마감재까지 시공 가능한지 직접 역산** |
| 셀별 편차와 좌표 | `cells.json` / `results.csv` | 구간별로 다른 마감을 적용할 때의 경계 산정 |
| 적용 기준 스냅샷 | `analyses.applied_criteria` | 판정의 근거가 된 기준을 추적 |
| 측정위치 계층 | `locations` (동·층·공간) | 마감재 물량 산정 단위와 직접 결합 |

**연계 방식 제안**: `analyses`를 참조하는 별도 테이블로 마감재 적합성을 기록하면, 본 시스템의
스키마를 수정하지 않고 확장할 수 있다. `analyses.stats`가 jsonb이고 계약 문서가 정본으로
관리되므로(`docs/contracts/stats-schema.md`) 소비자가 안정적으로 읽을 수 있다.

### 7.3 세부과업 3~4를 위해 유지한 것

- **데이터 포맷**: LAS/LAZ 지원으로 지상 레이저 스캐너(TLS) 데이터도 동일 파이프라인으로 처리
  가능하다. BIM 연계 시 좌표계 정합에 유리하다
- **좌표 프레임 계약**: 바닥 절대좌표와 벽 (u,v) 프레임의 3D 역매핑 공식이 계약 문서에
  규정되어 있어, BIM 모델 좌표계로의 변환 경로가 열려 있다
- **구배 알고리즘(세부과업 4) 관련**: 구역별 평면 계수(`zones[].plane_abc`)가 이미 산출되고
  저장되므로 설계 구배와의 대조에 바로 쓸 수 있다. 다만 현재는 판정이 **평면 제거 후 국부
  요철**만 보므로, 구배 자체의 적정성 판정은 별도 로직이 필요하다

## 8. 결론

과업지시서 세부과업 1이 요구한 성과물 가·나·다 항목을 **미이행 0건**으로 구현했고, 본 문서로
라 항목을 제출한다. 자동화 테스트 340건이 통과하며, 합성 데이터에서 ±1mm 정확도 게이트와
3천만 점 성능 게이트를 모두 충족한다.

동시에 다음을 분명히 밝힌다.

1. **실물 직선자를 이용한 현장 실측 대조는 수행되지 않았다.** 5.2절의 정확도는 합성 데이터에
   대한 것이며, 실제 현장에서의 정확도는 검증되지 않았다
2. **시방서 원문을 직접 대조한 판정 기준은 0건이다.** 전 11건이 2차 출처 교차검증 수준이다
3. **측정 불확도 U는 실측 근거가 없는 잠정치다**
4. **스캔 노이즈가 판정을 지배한다.** 노이즈 표준편차 1mm에서 이미 결함 없는 평면이 전 구간
   "경계"로 판정됨을 실측으로 확인했다
5. **벽면 판정은 현재 실질적으로 "경계 이상"만 산출한다.** 탑재된 벽면 평활도 기준 4종 중
   3종이 기본 U=8mm에서 적합 판정이 원리적으로 불가능하며(5.5절), 나머지 1종도 여유가 1mm뿐이다.
   시스템은 이 상태를 `uncertainty_swallows_pass` 경고로 표시하지만, 해소는 3번(U 확정)에
   달려 있다. **벽면 결과를 읽을 때 이 점을 반드시 감안해야 한다**(백로그 티켓 47)

1~3번은 현장 접근과 원문 확보라는 외부 조건이 필요한 항목이며, 4·5번은 1번의 결과에 따라 대응
방안을 결정해야 하는 항목이다. **본 시스템을 공식 검측 근거로 사용하려면 위 네 항목의 해소가
선행되어야 하며, 그 전까지는 설계 의도대로 스크리닝 도구로만 운용해야 한다.**
