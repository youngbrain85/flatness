# 세부과업 3 — 로봇 스캔 커버리지 계획·시뮬레이션 설계

작성 2026-08-10 · 상태: 설계 승인됨 (사용자, 2026-08-10)

## 1. 과업과 해석

과업지시서(7~9쪽)는 세부과업 3을 "BIM-API 기반 로봇 작업 모니터링 및 시뮬레이션"으로 정의한다.
사용자 확정 사항: **로봇의 작업은 청소가 아니라 LiDAR 스캔이며, 점군이 바닥 전체를 커버하도록
경로를 계획한다.** 이로써 세부과업 3은 나머지 셋을 잇는 고리가 된다 — 계획된 경로가 점군
밀도를 결정하고, 그 점군이 세부과업 1·4가 분석하는 입력이다.

두 스캔 모드를 모두 지원한다 (사용자 확정):

| 모드 | 장비 비유 | 동작 | 계획 문제 |
|---|---|---|---|
| **② 모바일** | 아이폰 LiDAR | 주행하며 연속 촬영. 전방 시야각 90° | 커버리지 경로계획 |
| **③ TLS** | 지상형 레이저 스캐너 | 거치점에 정지해 고정밀 촬영 | **거치점 배치 최적화** + 거치점 순회 경로 |

추가 확정: **시뮬레이션으로 커버리지가 차오르는 과정을 시각화**한다(프레임 PNG + GIF 애니메이션).

### 1.1 기술 사양 이탈 (9.2.1절 방침)

| 항목 | 지시서 | 이 설계 | 구속력 |
|---|---|---|---|
| 개발 환경 | C# + BIM-API | Python (기존 스택과 동일) | 없음 |
| 연계 환경 | ROS/ROS2 + Gazebo | **하이브리드**: 자체 엔진 + Gazebo 대조검증 (사용자 선택) | 없음 |
| 산출물 형식 | CSV·JSON·PNG·PDF | 그대로 이행 (+GIF 부가) | **있음** |

하이브리드의 뜻: 경로계획·커버리지·시뮬레이션은 자체 Python 엔진으로 구현해 통제·검증을
쉽게 하고, ROS 2 + Gazebo는 **같은 world에서 같은 경유점을 주행시켜 운행 거리·소요시간을
대조하는 검증 수단**으로 실제 설치·실행한다. 지시서의 ROS/Gazebo 연동 성과물이 실물로 남는다.

## 2. 아키텍처

```
도면 기하 (세부과업 2 spaces.outline + 8쪽 가구 장애물)
        │
        ▼
  점유격자 (occupancy grid, 셀 50mm)          ←── 공통 기반
        │
   ┌────┴──────────────────┐
   ▼                       ▼
② 모바일 모드              ③ TLS 모드
  커버리지 경로계획           거치점 배치 (탐욕 set cover)
  (boustrophedon + 보완)     + 순회 경로 (최근접 이웃 + 2-opt, 구간은 A*)
   └────┬──────────────────┘
        ▼
  시뮬레이터 (시간 스텝 주행 + 커버리지 누적)
        │
        ▼
  산출물: CSV(커버리지 시계열) · JSON(경로·거치점·상태 스트림)
          · PNG(프레임·최종 지도) · GIF(애니메이션) · PDF(보고서)
        │
        ▼
  Gazebo 대조검증 (운행 거리·소요시간 ±5%)
```

모듈은 최상위 `scansim/`이다. 입력은 세부과업 2의 DB 덤프(`dump.json` 계약 — `spaces[].outline`
링 배열, mm 정수)를 그대로 소비한다. 두 모드의 차이는 "어디서 보는가"뿐이고, 가시성 계산과
점 밀도 모델은 공유한다.

## 3. 커버리지 모델 — 판정 기준이 세부과업 1과 연결된다

셀마다 **추정 점 간격(mm)**을 계산한다. "커버됐다"의 기준은 면적이 아니라 점 밀도다 —
멀리서 스치듯 보인 셀은 면적으로는 커버지만 5mm 분석에는 쓸 수 없다.

| 모드 | 점 간격 모델 | 목표 등급 (기본값) |
|---|---|---|
| ② 모바일 | `max(거리 × 각해상도, 주행속도 ÷ 스캔율)` | ≤ 20mm (스크리닝급) |
| ③ TLS | `거리 × 각해상도 ÷ cos(입사각)` | ≤ **5mm** (세부과업 1 해상도 요구) |

- 가려짐(occlusion): 점유격자 위 레이캐스트. 가구 뒤 그림자가 실제로 생긴다.
- 임계값·장비 파라미터(각해상도·스캔율·사거리)는 하드코딩하지 않고 설정 데이터로 둔다
  (이 프로젝트 관례). **기본값은 장비 공표치가 아니라 모델 파라미터이며 그렇게 표기한다** —
  실제 장비가 정해지면 값만 바꾼다.
- 누적 규칙: 같은 셀을 여러 번 보면 **최소 점 간격**(가장 촘촘한 관측)을 취한다.

## 4. ② 모바일 모드

- 이동 가능 영역: 점유격자를 로봇 반경만큼 팽창(inflate)한 자유공간.
  세부과업 2의 단차 판정과 결합한다 — 지정한 로봇 등급이 넘지 못하는 경계(`fail`/`unknown`)는
  벽으로 취급한다.
- 경로: boustrophedon(왕복) 분해 기본 + 시야각 90° 부채꼴 스윕으로 커버리지 누적.
  잔여 미커버 영역(가구 그림자)에 보완 경유점을 탐욕적으로 추가한다.
- 산출: 경로 폴리라인, **운행 거리**, 예상 소요시간, 최종 커버리지율(밀도 등급별).

## 5. ③ TLS 모드

**두 단계 최적화.**

1. **배치 (set cover)**: 자유공간 격자 후보점마다 가시영역과 밀도 기여를 계산하고, 탐욕
   알고리즘으로 "목표 밀도 미달 셀"이 없어질 때까지 거치점을 추가한다. set cover는 NP-hard이며
   탐욕 근사(근사비 ln n)임을 산출물에 명시한다.
2. **순회 (TSP 근사)**: 선택된 거치점을 최근접 이웃으로 잇고 2-opt로 개선한다. 거치점 간
   구간 경로는 A* 최단경로(②의 격자·팽창을 재사용).

산출: 거치점 좌표·수, 거치점별 커버 기여, 순회 순서와 구간 경로, **총 운행 거리**,
거치점당 체류시간 포함 총 소요시간, **거치점 수 vs 커버리지 트레이드오프 곡선**
(지시서의 "장애물 및 환경 조건 반영 경로 비교·검토" 요구를 채운다).

## 6. 시뮬레이션·시각화

시간 스텝(기본 0.2s)으로 로봇을 경로 위에서 전진시키며:

- 각 스텝에서 시야(② 부채꼴 / ③ 거치점 스캔)를 커버리지 격자에 누적
- **프레임 PNG 연속 + GIF 애니메이션**: 로봇 위치·궤적·밀도별 커버 영역·미커버 영역
- **커버리지-시간 곡선 CSV/JSON**: 시각별 등급별 커버율
- 모니터링 요구("로봇 위치·이동 상태·작업 수행 정보")는 시뮬레이션 상태 스트림(JSON,
  스텝별 위치·헤딩·모드·누적 거리·누적 커버율)이 채운다

## 7. 검증

이 프로젝트의 방식 그대로: 근거 있는 대조 + 변이 저항 + 무변이 대조군.

1. **해석적 대조**: 빈 정사각형 방은 정답이 손계산된다 —
   TLS 1거치점의 커버 면적(사거리 원 ∩ 방), 모바일 직선 1패스의 스윕 면적, A* 최단거리.
   시뮬레이터 결과가 해석값과 일치해야 한다(격자 이산화 오차 한계 명시).
2. **불변식 (변이 실험 대상)**: 커버리지는 시간에 단조 증가한다 / 장애물을 추가하면 절대
   늘지 않는다 / 거치점을 추가하면 절대 줄지 않는다 / 경로 길이는 직선거리 이상이다 /
   A* 경로는 장애물 셀을 지나지 않는다.
3. **Gazebo 대조검증**: WSL Ubuntu 24.04에 ROS 2 Jazzy + Gazebo Harmonic을 실제 설치.
   세대 기하를 SDF world로 변환하고 차동구동 로봇이 같은 경유점을 따라가게 해
   **운행 거리·소요시간을 자체 시뮬레이터와 대조한다 (허용 오차 ±5%)**. 이 대조가 실패하면
   실패로 보고한다 — 성공할 때까지 허용 오차를 늘리지 않는다.

## 8. 범위에서 뺀 것 (YAGNI)

- 실시간 로봇 제어·SLAM — 시뮬레이션 과업이지 실기 운용 과업이 아니다
- 대시보드 인터랙티브 뷰어 — 산출물 형식(CSV·JSON·PNG·PDF)에 없다. GIF+PDF로 충족
- 3D 커버리지(벽·천장) — 지시서가 "바닥면 형상"을 명시하므로 바닥 2D로 한정
- 다층·다세대 — 검증된 도면이 26형 한 세대뿐이다 (세부과업 2 한계 1과 동일)

## 9. 알려진 한계 (설계 시점)

1. **장비 파라미터가 가정값이다.** 각해상도·스캔율·사거리의 기본값은 모델 파라미터이며
   특정 장비의 공표 사양이 아니다. 실제 장비 확정 시 값 교체가 필요하다.
2. **가구 장애물은 도면 8쪽에서 추출하며, 추출 정확도는 실 경계(0.003%)만큼 검증할 정답이
   없다.** 도면에 가구 면적표가 없기 때문이다. 육안 대조 + 개수 확인으로 갈음하고 그 사실을
   명시한다.
3. **탐욕 set cover는 최적해를 보장하지 않는다.** 근사비 ln n을 명시한다.
4. **Gazebo 대조는 운동학(거리·시간)까지다.** 센서 시뮬레이션(점군 생성)은 자체 모델이며
   Gazebo 센서 플러그인과의 대조는 범위 밖이다.
5. 도면의 가구 배치는 "점선표기 시설물은 미설치 대상"(1쪽 주기 19)일 수 있다 — 어떤 가구가
   실제 입주 시 존재하는지는 도면으로 확정되지 않는다. 장애물 유/무 두 시나리오를 다 낸다.
