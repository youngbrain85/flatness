# 대시보드 "계측 콘솔" 리디자인 + 흐름 단순화 — 설계

승인: 2026-08-11 (방향 A "계측 콘솔" 선택 → 흐름 단순화 포함 전체 승인, 구현까지 위임)

## 1. 목표

1. **전문가적·엔지니어링 톤의 시각 디자인** — Mobbin 레퍼런스 3종을 근거로 한다.
   - Vercel (Developer Tools): 좌측 사이드바 내비, 상태 점(● Ready), 모노스페이스 로그
     테이블, 무채색 + 의미색만 컬러, 주 버튼 검정.
   - Linear: 밀도 높은 목록(상태 아이콘·칩·우측 정렬 메타·그룹 헤더), 조용한 회색 팔레트.
   - Stripe: 지표 카드(라벨 좌 / tabular 숫자 우), 기간·갱신 시각 표기, 미니 분포 시각화.
2. **흐름 단순화** — 신규 사용자의 첫 PDF까지 화면 이동 12번 → 5번.
   근거: 2026-08-11 흐름 탐사(라우트 14종 전수). 이동 12번 중 3번은 분석 결과 화면에
   보고서 생성 링크가 없어 되돌아가는 순수 우회였다.

## 2. 범위 / 비범위

**범위**: `dashboard/` 화면·링크·폼 로직·디자인 토큰·공통 컴포넌트. 전 라우트.
**비범위(하지 않는 것)**:
- 서버 스키마·워커·엔진 변경 없음. Supabase 쿼리는 화면 필요에 따른 조회 추가만 허용.
- 다크 모드 없음 — 산출물 PNG(히트맵·편차맵·높이 뷰)가 흰 배경이라 이질적이고,
  과거 다크 모드 캐스케이드 사고(판독 불가) 이력이 있다(globals.css 주석).
- 차트 라이브러리 추가 없음. 산출물 PNG는 그대로 쓴다. 미니 분포바는 CSS로 그린다.
- 정합(registration)·설정 화면의 **기능** 변경 없음 — 토큰·브레드크럼만 입힌다.

## 3. 디자인 토큰 (globals.css `@theme`)

- **팔레트**: zinc 중립 — 페이지 배경 `zinc-50`, 카드 `white`, 보더 `zinc-200`,
  본문 `zinc-900`, 보조 텍스트 `zinc-500`. 주 버튼 = `zinc-900`(검정, hover `zinc-700`).
  기존 `blue-700` 액센트는 제거한다.
- **의미색(판정 전용)**: 적합 `green-600` / 주의 `amber-500` / 재시공 `red-600` /
  판정 불가·미상 `zinc-400`. 배지 배경은 각 `-50`, 텍스트는 각 `-700`.
  이 4색 외에 컬러를 쓰지 않는다(링크 hover 포함).
  예외: '외부 결과'(임포트 출처 경고) 배지는 4종 어느 쪽으로도 오독되지 않도록
  purple을 유지합니다(C1 사고 계열의 출처 경고).
- **타이포**: 본문 Noto Sans KR, 수치·ID·단위·좌표·일시 = Geist Mono +
  `font-variant-numeric: tabular-nums`. 둘 다 `next/font/google`(빌드 타임 페치,
  저장소에 폰트 파일을 넣지 않는다). Pretendard는 Google Fonts에 없어 제외.
  수치는 값과 단위를 분리해 렌더한다(예: `3.2` mm — 단위는 보조색 12px).
- **형태**: 보더 1px, 라운드 6px(rounded-md), 섀도 없음(팝오버·드로어만 sm),
  행 패딩 `py-2`(밀도 우선), 카드 패딩 `p-4`.

## 4. 레이아웃

- **데스크톱(≥md)**: 좌측 고정 사이드바 220px — 상단 로고(Flatness, 모노스페이스),
  메뉴: 현장 / 보고서 / 업로드 / 설정 (Tabler류 아이콘 없이 텍스트+활성 표시 좌측 2px 바),
  하단: 사용자 이메일(모노 12px)·로그아웃. 본문은 사이드바 옆 전체 폭(`max-w` 제거,
  내부 콘텐츠만 `max-w-7xl`).
- **모바일(<md)**: 상단 바(로고+햄버거) + 슬라이드 드로어(동일 메뉴).
- 활성 메뉴 판정은 pathname prefix. `components/nav.tsx`는 sidebar로 대체하되
  서버 컴포넌트 유지(사용자 이메일 조회), 드로어 토글만 클라이언트 섬.

## 5. 공통 컴포넌트 (`components/ui/`)

| 컴포넌트 | 역할 | 비고 |

| `StatusDot` | ● + 라벨. 판정·잡 상태 공용 | 색은 §3 의미색 4종 + 진행 중(pulse 없는 zinc-500) |

| `DataTable` | 밀도 테이블 래퍼(thead 12px 대문자 아님·보조색, 수치 열 우측 정렬·모노) | 정렬·페이지네이션 없음(현재 데이터 규모) |

## 6. 흐름 변경 (승인된 5건)

### 6.1 스캔 작업대 통합 (`/scans/[id]`)
- 한 화면에서: 메타 헤더(브레드크럼 포함) → 상태 스트립(업로드→사전검사→단위확정→분석→완료
  단계 표시) → **단위 확정 섹션 인라인**(`awaiting_unit_confirm`일 때 높이 뷰 + 단위 라디오 +
  확정 버튼 — 기존 `unit-confirm-form` 재사용) → 평활도/구배 결과 섹션(완료된 현재 분석의
  결과를 **인라인 렌더** — 기존 `AnalysisResult`/`SlopeResult` 재사용) → 이전 분석 이력.
- `/analyses/[id]` → `redirect(/scans/[scanId]?analysis=[id])` (서버 리다이렉트, 기존
  링크·북마크 보존). `/scans/[id]/confirm-unit` → `redirect(/scans/[id])`.
- 이력의 과거 분석 선택 시: 쿼리 파라미터 `?analysis=[id]`로 해당 분석을 렌더(기본은 최신).

### 6.2 업로드 셀프서비스 (`/upload`)
- 현장+측정위치 이중 셀렉트 → **현장별 `<optgroup>` 단일 셀렉트**.
- 셀렉트 옆 "+ 새 측정위치" → 인라인 미니 폼(현장 선택/신규 현장명 + 동·층·공간) —
  기존 `new-site-form`·`new-location-form`의 insert 로직 재사용. 생성 즉시 선택 상태로.
- 측정위치 0개여도 폼을 숨기지 않는다(인라인 생성이 빈 상태의 해법).
- **버그 수정**: `?location=`만 있는 진입에서 프리필이 버려지는 문제 —
  location으로 site를 역산해 함께 프리필한다.

### 6.3 결과 → 보고서 원클릭
- 스캔 작업대의 완료된 분석 섹션 헤더에 "이 위치의 보고서 생성" 버튼 →
  `/reports/new?location=[locationId]`.
- `/reports/new`는 `location` 파라미터가 없으면 `notFound()` 대신 **측정위치 선택
  드롭다운**을 먼저 보여준다(선택 시 같은 화면에서 후보 로드).
- `/reports` 목록(필터 없음)에도 "새 보고서" 버튼 상시 노출 → `/reports/new`.

### 6.4 막다른 화면 제거
- 전 상세 화면에 PageHeader 브레드크럼: 스캔 작업대(현장 › 측정위치), 보고서 상세(현장 ›
  측정위치), 정합(현장 › 측정위치).
- `failed` 스캔: `/upload?site=&location=` 재시도 링크. 빈 `/reports`: 위 6.3.
- `/settings`: 브레드크럼(홈 ›)만. 업로드 빈 상태의 `sites[0]` 하드코딩 제거(6.2로 소멸).

### 6.5 홈 개편 (`/`)
- 상단 지표 스트립(MetricCard 4개): 현장 수 / 스캔 수 / **처리 중**(precheck·analyze·report
  진행 건수) / 판정 분포(적합·주의·재시공 미니바).
- 현장 카드 그리드 → DataTable: 현장명, 측정위치 수, 스캔 수, 최근 측정일(모노), 판정
  분포 미니바, 행 클릭 → 현장 상세. 빈 상태는 기존 3단계 안내 유지하되 EmptyState로.

## 7. 검증

1. 기존 대시보드 테스트 전부 통과 + 리다이렉트(analyses→scans)·프리필 수정의 신규 테스트.
2. dev server에서 화면별 스크린샷 캡처 대조(사용자 상시 지시): 홈·현장·업로드·스캔
   작업대(대기/단위확정/완료 각 상태)·보고서 목록/생성/상세·설정·로그인. 콘솔 오류 0.
3. 모바일 뷰포트(375px) 스크린샷 — 사이드바 드로어 동작.
4. 첫 PDF까지 클릭 경로를 dev 환경에서 실제로 밟아 5회 이동임을 확인.

## 8. 구현 주의

- 이 저장소의 Next.js는 관례가 다르다 — **구현 전 `dashboard/node_modules/next/dist/docs`
  의 해당 가이드를 읽는다**(`dashboard/AGENTS.md`).
- 서버 컴포넌트 우선 유지. 기존 realtime 감시(`ScanStatusWatcher`·`AnalysisProgress`·
  `ReportProgress`) 로직은 재사용하고 UI만 교체.
- 코드 주석은 한국어, 알고리즘·라이브러리 이름은 영어 그대로.
