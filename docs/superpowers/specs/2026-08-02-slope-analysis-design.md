### 1.3 기술 사양에서 의도적으로 벗어나는 부분

과업지시서 11쪽은 주요 라이브러리로 Open3D·PCL·NumPy·scikit-learn을 명시한다.
사용자 결정(2026-08-02)에 따라 **언어·라이브러리 제약은 결과로 판단**하며, 실제
구현은 다음과 같이 간다.

- 평면 피팅: 기존 자체 RANSAC(NumPy) 유지. 잘 동작하는 코드를 scikit-learn으로
  교체하면 회귀 위험만 생기고 얻는 것이 없다
- ICP: SciPy `cKDTree` 기반 point-to-plane 직접 구현. Open3D는 설치 용량이
  400MB대라 이미 Chromium이 들어간 워커 컨테이너를 크게 불린다
- PCL: C++ 라이브러리라 파이썬 스택에 넣지 않는다

**이 차이는 `docs/service-report.md`의 미이행·부분이행 절에 기록한다.** 발주처
제출 문서이므로 숨기지 않는다.

## 3. 데이터 모델 (마이그레이션 006)

### 3.1 분석 종류를 새 차원으로 추가

표면 유형(`surface_type`: floor/wall)은 그대로 두고 분석 종류를 분리한다. 구배는
표면의 종류가 아니라 **같은 바닥을 보는 다른 방식**이므로 `surface`에 'slope'를
넣는 것은 의미가 어긋난다.

```sql
create type analysis_kind as enum ('flatness', 'slope');
alter table analyses  add column kind analysis_kind not null default 'flatness';
alter table criteria  add column kind analysis_kind not null default 'flatness';
```

기본값이 'flatness'라 기존 행과 코드는 그대로 동작한다.

### 3.2 현재 분석 유니크 인덱스 재정의

```sql
-- 기존: create unique index analyses_current on analyses(scan_id)
--         where is_current and deleted_at is null;
drop index analyses_current;
create unique index analyses_current on analyses(scan_id, kind)
  where is_current and deleted_at is null;
```

이렇게 하지 않으면 구배 분석이 평활도 분석을 밀어낸다.

### 3.3 기준 조회 함수 확장

`fn_resolve_criteria(site_id, surface)`에 `kind` 인자를 추가한다. 기존 호출부가
깨지지 않도록 기본값 `'flatness'`를 준다.

### 3.4 구배 기준 thresholds 형태

`criteria.thresholds`는 jsonb 배열 제약(`jsonb_typeof = 'array'`)이 걸려 있으므로
그 안에서 담는다.

```json
[{
  "use": "주차장 배수",
  "design_pct": 2.0,
  "pass_pct": 0.5,
  "re_pct": 1.5,
  "dir_pass_deg": 30
}]
```

- `design_pct`: 설계 구배(%)
- `pass_pct`: 적합으로 볼 크기 편차 한계
- `re_pct`: 이를 넘으면 재시공
- `dir_pass_deg`: 적합으로 볼 방향 편차 한계(도)

시드할 용도는 주차장 배수·욕실 바닥·옥상 슬래브·실내 평바닥 4종으로 시작한다.

**구체적 수치는 이 문서에서 정하지 않는다.** 임의로 지어내면 판정 전체가 근거
없는 값 위에 서게 된다. 구현 단계에서 각 용도의 설계 구배를 출처와 함께 조사해
`criteria.source_text`에 적고, 원문 대조 여부를 `docs/criteria-sources.md`와 같은
방식으로 표기한다. 세부과업 1에서 판정 기준 11종의 **원문 대조가 0건**(2차 출처
교차검증만)이었던 전례가 있으므로, 대조하지 못한 항목은 그렇다고 명시한다.

### 3.5 판정 파라미터

배수구 위치는 기존 `analyses.params jsonb`에 넣는다. 마이그레이션이 필요 없다.

```json
{ "drain_points": [{ "x": 3.2, "y": 5.1 }] }
```

### 3.6 정합 이력

```sql
create table registrations (
  id uuid primary key default gen_random_uuid(),
  source_scan_ids uuid[] not null,
  correspondences jsonb not null,   -- [{a:{x,y,z}, b:{x,y,z}}, ...]
  transform jsonb,                  -- 4x4 행렬
  rmse_mm double precision,
  iterations int,
  status text not null default 'awaiting_points',
  error_text text,
  result_scan_id uuid references scans(id),
  created_by uuid references profiles(id),
  created_at timestamptz not null default now()
);
```

정합 RMSE는 과업지시서 12쪽이 요구하는 "평면 피팅 오차 검증 데이터"에 대응한다.

### 3.7 보고서 소프트 삭제

```sql
alter table reports add column if not exists deleted_at timestamptz;
```

**발행본 불변 트리거를 함께 손봐야 한다.** 현재 `fn_reports_finalized_guard`는
`before update`에서 내용 컬럼 변경을 막는데, 소프트 삭제도 UPDATE이므로 잠금 대상
목록에 `deleted_at`을 넣지 않아야 발행본을 지울 수 있다. `gen_status`를 열어 둔
것과 같은 이유다. DELETE는 지금도 트리거가 막지 않는다.

### 4.2 구배 산출

서브셀 격자(기본 5cm)는 평활도와 공유하고 집계 단위만 2m로 바꾼다. 2m 셀 하나가
40×40 서브셀이다.

**셀별 평면 피팅은 원점군이 아니라 서브셀 중앙값에 한다.** 이유는 셋이다.

1. 노이즈가 중앙값 단계에서 이미 걸러진다
2. 점 밀도 불균일의 영향이 사라진다. 원점군에 그대로 피팅하면 스캐너에 가까워
   점이 빽빽한 구역이 평면을 끌어당긴다. 서브셀 중앙값은 면적당 균등하다
3. 계산량이 수천분의 1이다

산출값은 평면 `z = a·x + b·y + c`에서 다음과 같이 얻는다.

- 구배 크기(%) = `sqrt(a² + b²) × 100`
- 구배 방향(rad) = `atan2(b, a)`
- 피팅 잔차 RMSE
- 기울기 표준오차 (4.3 참고)

### 4.3 셀별 불확도

평활도는 전역 상수 `U`를 썼고, 그 탓에 벽면 기준 4종 중 3종이 U=8mm에서 적합
판정 자체가 불가능해지는 문제가 있다(백로그 티켓 47). 구배는 그럴 필요가 없다.
최소제곱 평면 피팅이 기울기 계수의 표준오차를 직접 준다.

```
se(기울기) ≈ 잔차 RMSE / (sqrt(N) · sd(좌표))
```

셀마다 점 개수와 잔차가 다르므로 불확도도 셀마다 다르게 나온다. 데이터가 좋은
셀은 좁은 불확도로 단정하고, 나쁜 셀만 경계로 빠진다.

### 4.4 정합

- 입력: 두 점군 + 대응점 3쌍 이상
- 1단계: Umeyama/Kabsch로 강체 변환을 닫힌 형태로 계산(축척 고정)
- 2단계: point-to-plane ICP로 정밀화. 대응 탐색은 SciPy `cKDTree`
- 수렴: 직전 반복 대비 RMSE 변화율 `< 1e-4`, 또는 최대 반복 50회 도달
- 성공 임계: 최종 RMSE `≤ 2mm`. 요구 정밀도 ±5mm보다 충분히 작게 잡는다
- 출력: 4×4 변환행렬, 최종 RMSE, 반복 횟수, 수렴 여부

대응점 클릭은 화면 해상도 수준(10cm/픽셀이면 ±5cm)이므로, 요구 정밀도 ±5mm를
맞추려면 ICP 단계가 반드시 필요하다.

## 5. 판정 규칙

### 5.1 등급

평활도의 4등급을 그대로 쓴다. 같은 스캔에 두 분석 결과가 나란히 뜨므로 색과
어휘가 다르면 혼란스럽다.

| 등급 | 구배에서의 의미 |
|---|---|
| 적합 | 크기·방향 모두 허용 안 |
| 경계 | 불확도 폭이 허용 경계를 걸쳐 단정 불가 |
| 보수 | 허용을 벗어났으나 국소 보정으로 해결 가능 |
| 재시공 | 편차가 매우 크거나 역구배 |

### 5.2 판정 절차 (셀 단위)

기호: `g` = 실측 구배(%), `u` = 셀별 구배 불확도(%, 4.3의 표준오차를 %로 환산),
`d = |g − design_pct|`, `θ` = 실측 방향과 기대 방향의 각도 차.

기대 방향은 셀 중심에서 **가장 가까운 배수구 점**을 향하는 방향이다. 배수구가
지정되지 않으면 방향 판정(3·4번)을 건너뛴다.

1. **판정 불가 걸러내기.** 유효 서브셀이 10개 미만이면 평면이 수치적으로 결정되지
   않으므로 제외한다. 또한 `u > pass_pct`이면 그 셀은 애초에 적합·부적합을 가릴
   해상도가 없으므로 제외한다. 서브셀이 적거나 잔차가 크면 `u`가 커지므로 이
   한 조건이 "점 부족"과 "요철 심함"을 함께 처리한다. 제외된 셀은
   `coverage_pct`에서 빠지고 "구배 신뢰 불가" 경고를 남긴다
2. **역구배 우선.** `θ > 90°`이면 물이 설계와 반대로 흐르므로 크기와 무관하게
   **재시공**이다. 여기서 판정을 끝낸다
3. **재시공.** `d − u > re_pct` → 재시공
4. **적합.** `d + u ≤ pass_pct` 이고 `θ ≤ dir_pass_deg` → 적합
5. **보수.** `d − u > pass_pct` 이거나 `θ > dir_pass_deg` → 보수
6. **경계.** 위 어디에도 확정적으로 걸리지 않는 셀. 불확도 폭이 허용 경계를
   걸쳐 단정할 수 없는 경우다

`u`를 더하고 빼는 방향에 주의한다. 적합은 불확도를 감안해도 확실히 안쪽일 때만
주고(`d + u`), 재시공은 불확도를 감안해도 확실히 바깥일 때만 준다(`d − u`).
그 사이는 경계로 남긴다.

### 5.3 보정 방향

실측 벡터에서 설계 벡터를 빼면 보정 벡터가 나온다. 이를 %로만 보여주면 시공자가
쓸 수 없으므로 **높이차로 환산한다.** 2m 셀에서 구배 0.5% 차이는 양단 높이차
10mm다. 결과표에는 "북동쪽 끝을 10mm 낮춤" 형태로 적고, 지도에는 화살표로 그린다.

### 5.4 통계

과업지시서 명시 항목을 그대로 낸다. 구간별 평균편차·표준편차·최대편차이며,
"구간"은 기존 구역화(`core/zones.py`) 결과를 쓴다. 레벨이 다른 구역은 설계 구배도
다를 수 있으므로 구역별로 나눠 낸다.

## 6. 정합 흐름

### 6.1 precheck를 살려 높이 뷰를 만든다

현재 `handle_precheck`는 `unit_scale` 유무만 보고 상태를 승격한다. 여기서 **위에서
내려다본 높이 뷰 PNG**를 만들면 세 가지가 한 번에 풀린다.

- 정합: 대응점을 찍을 화면이 생긴다
- 배수구 지정: 분석 전에 배수구를 정할 수 있다
- 단위 확정 화면: 지금은 파일명과 라디오 버튼만 보여줘 사용자가 무엇을 확정하는지
  알 수 없다. 그림이 있으면 "이 방이 8m인가 80cm인가"를 눈으로 판단할 수 있다

단위 확정 전이라 축척을 모르지만 상대 좌표로 그리면 되고, 오히려 범위 판단에
도움이 된다.

### 6.2 단계

1. 두 스캔을 각각 업로드(기존 경로 그대로). precheck가 각각 높이 뷰를 만든다
2. 정합 시작 → `registrations` 행 생성(`status='awaiting_points'`)
3. 두 뷰를 나란히 놓고 번갈아 클릭해 대응점 쌍을 만든다. 최소 3쌍, 권장 4쌍 이상.
   Z는 클릭한 XY 위치의 서브셀 중앙값에서 읽는다
4. 정합 잡 실행 → Umeyama → ICP → 변환행렬·RMSE
5. RMSE가 납득되면 병합 스캔 생성

### 6.3 병합 산출물은 서브셀 중앙값 점군

두 문제를 동시에 푼다.

**중첩 영역 보완**(과업지시서 명시): 중첩 서브셀에 두 소스의 점이 함께 들어가고
중앙값이 뽑히므로, 별도 가중치 없이 이상치에 강하게 통합된다.

**파일 크기**: 두 점군을 그대로 이어붙이면 Storage 버킷의 50MB 상한에 걸린다.
5cm 서브셀 중앙값이면 600 m² 바닥이 약 24만 점, 3MB 수준이다. 분석은 어차피
서브셀 중앙값만 쓰므로 **결과가 동일하다.**

원본 두 개는 그대로 남고 `registrations`가 소스와 결과를 잇는다.

### 6.4 잡 타입

기존 잡 타입은 `precheck`·`analyze`·`import`·`report` 4종이다. 다음이 더해진다.

| 잡 타입 | 하는 일 | 무게 |
|---|---|---|
| `analyze` (kind='slope') | 점군 → 2m 셀 구배 벡터 산출 | 무거움 |
| `slope_judge` | 산출된 셀 벡터 + 배수구 위치 → 판정·산출물 갱신 | 가벼움(점군 미열람) |
| `register` | 대응점 → Umeyama → ICP → 병합 스캔 생성 | 무거움 |

`precheck`의 계약이 바뀐다. 지금은 상태 승격만 하지만, 앞으로는 **높이 뷰 PNG를
만들어 Storage에 올린 뒤** 상태를 승격한다. 기존 스캔은 이 그림이 없으므로 화면은
그림이 없을 때를 견뎌야 한다.

`analyze` 잡은 `analyses.kind`를 보고 평활도·구배 파이프라인으로 분기한다. 잡
타입을 새로 만들지 않는 이유는, 워커가 이미 `analysis_id`로 행을 읽으므로 종류가
그 안에 들어 있기 때문이다.

## 7. 대시보드 화면

### 7.1 분석 시작

스캔 상세에 "평활도 분석" / "구배 분석" 두 버튼. 같은 스캔에 둘 다 돌릴 수 있고
`analyses.kind`가 다르므로 서로를 밀어내지 않는다. 결과 화면에 탭으로 나란히 붙는다.

### 7.2 구배 결과 화면

평활도 화면의 구조를 따른다.

- 구배 크기 히트맵(4등급 색) + 방향 화살표 오버레이
- 상단에 "배수구 위치를 클릭하세요" 안내. 클릭하면 재판정 잡이 돌고 갱신된다
- 결과표: 셀별 구배 %, 설계 대비 편차, 보정 높이차(mm), 등급
- 구역별 통계

**역구배 셀은 색만으로 드러나지 않는다.** 크기가 정상이면 초록인데 물은 반대로
흐른다. 화살표를 굵게 하고 결과표에 별도 표시한다.

### 7.3 재판정

분석은 배수구 없이 한 번만 돌려 셀별 구배 벡터를 산출물로 남긴다. 배수구를
클릭하면 그 산출물만 읽어 판정을 다시 한다(점군을 읽지 않으므로 수 초).

판정 로직을 브라우저에서 미리 계산해 즉시 보여주는 방식은 **의도적으로 피한다.**
판정이 파이썬 엔진과 브라우저 두 곳에 생기고, 세부과업 1에서 같은 종류의 이중화가
실제로 어긋난 전례가 있다.

### 7.4 정합 화면

두 스캔을 나란히 놓고 번갈아 클릭한다. 찍은 쌍이 목록으로 쌓이고 3쌍 이상이면
"정합 실행"이 활성화된다. 결과 RMSE를 보여주고, 납득되면 "병합 스캔 만들기"로
확정한다. RMSE가 나쁘면 대응점을 다시 찍게 한다.

### 7.5 단위 확정 화면

precheck가 만든 높이 뷰를 표시한다.

### 7.6 보고서 삭제

보고서 목록과 상세 양쪽에 둔다. 소프트 삭제이며 목록에서 거른다. 발행본을 지울
때는 확인 문구를 다르게 보여준다. Storage의 PDF 파일은 남긴다(백로그 티켓 58과
같은 정책, 정리 잡으로 일괄 처리).

## 8. 오류 처리

| 상황 | 처리 |
|---|---|
| 셀 내 서브셀 부족 | 판정 불가. `coverage_pct`에서 제외 |
| 피팅 RMSE 과대(요철 심함) | 판정 불가 + "구배 신뢰 불가" 경고 |
| 배수구 미지정 | 크기만 판정, 방향은 실측값 표시만 |
| 대응점 3쌍 미만 또는 공선 | 정합 거부, 사유 표시 |
| ICP 발산 또는 RMSE 임계 초과 | 정합 실패로 반환. 삼키지 않는다 |
| 병합 결과가 Storage 상한 초과 | 실패로 반환하고 서브셀 크기 조정을 안내 |
| 잡 등록 실패 | 이번 제출로 만든 행을 되돌린다(기존 관례) |

## 9. 테스트·검증

### 9.1 구배 산출

합성 데이터로 게이트를 건다. **알려진 구배**(예: 2.0%, 방향 45°)의 평면을 생성하고
노이즈를 주입한 뒤 산출값을 대조한다.

- 과업지시서 요구 분석 오차율 **±5% 이내**를 게이트로 건다
- 노이즈 수준별(0.5·1·2·5mm)로 산출 오차를 실측해 기록한다. 구배는 2m 셀에
  수천 개 서브셀을 피팅하므로 평활도보다 노이즈에 훨씬 강할 것으로 보이나,
  **수치는 실측으로 확인한다**

### 9.2 판정

- 역구배 케이스: 크기는 설계와 같고 방향만 180° 반대 → 재시공이 나와야 한다
- 경계 케이스: 편차가 허용 경계에 불확도 폭으로 걸치는 셀 → 경계
- 배수구 미지정 시 방향 판정을 건너뛰는지

### 9.3 정합

알려진 강체 변환(회전 + 평행이동)을 걸고 노이즈와 부분 중첩을 준 뒤, 정합이 그
변환을 오차 안에서 복원하는지 확인한다. 실물 데이터 없이도 정확도를 증명할 수 있다.

- **복원 게이트**(노이즈 1mm, 중첩 50%): 회전 오차 `≤ 0.1°`, 평행이동 오차 `≤ 1mm`.
  요구 정밀도 ±5mm보다 충분히 작게 잡는다
- 대응점에 ±5cm 오차(화면 클릭 정확도 수준)를 준 상태에서 ICP가 위 게이트까지
  회복하는지. **이것이 반자동 정합의 핵심 가정이므로 반드시 검증한다**
- 중첩이 거의 없는 경우(10% 미만) 성공을 가장하지 않고 실패로 끝나는지

### 9.4 회귀

평활도 분석 결과가 이번 변경으로 달라지지 않아야 한다. 기존 스위트(엔진 139 /
워커 92 / 대시보드 143)가 전부 통과해야 한다.

## 10. 구현 순서

이 스펙은 엔진·마이그레이션·워커·대시보드·문서에 걸쳐 있어 **하나의 계획으로 묶기에는
크다.** 다음 순서로 나눠 각각이 독립적으로 동작하는 상태로 끝나게 한다.

| 단계 | 내용 | 끝났을 때 |
|---|---|---|
| A | 보고서 삭제 | 세부과업 4와 무관한 별건. 작아서 먼저 털고 간다 |
| B | 엔진 구배 산출 + CLI | 점군에서 2m 셀 구배가 나오고 CLI로 확인된다 |
| C | 마이그레이션 006 + 워커 분기 + 기준 시드 | 대시보드에서 구배 분석을 돌릴 수 있다 |
| D | 구배 결과 화면 + 배수구 클릭 + 재판정 | 판정과 보정 방향까지 화면에서 완결된다 |
| E | precheck 높이 뷰 + 단위 확정 화면 개선 | 정합 UI의 전제가 갖춰진다 |
| F | 정합 엔진 + 정합 화면 + 병합 스캔 | 멀티 소스 정합이 동작한다 |
| G | 스캔 가이드라인 문서 + 용역 보고서 갱신 | 과업지시서 문서 성과물이 채워진다 |

E가 F보다 앞인 이유는 대응점 클릭 화면이 높이 뷰에 의존하기 때문이다. B가 C보다
앞인 이유는 엔진 산출 형태가 확정돼야 DB 스키마와 산출물 규약을 정할 수 있기
때문이다.

## 11. 범위 밖

- **드론·터틀봇 실물 데이터 연동**: 반자동 정합은 대응점만 있으면 소스를 가리지
  않으므로 알고리즘은 데이터에 무관하다. 실물 데이터가 확보되면 검증만 추가한다
- **자동 특징 매칭**: 대응점 자동 검출은 하지 않는다
- **옥외 대면적 성능**: 현재 성능 게이트(3천만 점, 5분, 2GiB)를 그대로 쓴다
- **Storage 고아 파일 정리**: 백로그 티켓 58
