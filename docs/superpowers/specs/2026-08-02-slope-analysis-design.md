### 1.3 기술 사양에서 의도적으로 벗어나는 부분

과업지시서 11쪽은 주요 라이브러리로 Open3D·PCL·NumPy·scikit-learn을 명시한다.
사용자 결정(2026-08-02)에 따라 **언어·라이브러리 제약은 결과로 판단**하며, 실제
구현은 다음과 같이 간다.

- 평면 피팅: 기존 자체 RANSAC(NumPy) 유지. 잘 동작하는 코드를 scikit-learn으로
  교체하면 회귀 위험만 생기고 얻는 것이 없다
- ICP: SciPy `cKDTree` 기반 point-to-plane 직접 구현. Open3D는 설치 용량이
  400MB대라 이미 Chromium이 들어간 워커 컨테이너를 크게 불린다
- PCL: C++ 라이브러리라 파이썬 스택에 넣지 않는다

**이 차이는 `docs/service-report.md`의 미이행·부분이행 절에 기록한다.** 발주처
제출 문서이므로 숨기지 않는다.

## 3. 데이터 모델 (마이그레이션 007)

### 3.1 분석 종류를 새 차원으로 추가

표면 유형(`surface_type`: floor/wall)은 그대로 두고 분석 종류를 분리한다. 구배는
표면의 종류가 아니라 **같은 바닥을 보는 다른 방식**이므로 `surface`에 'slope'를
넣는 것은 의미가 어긋난다.

```sql
create type analysis_kind as enum ('flatness', 'slope');
alter table analyses  add column kind analysis_kind not null default 'flatness';
alter table criteria  add column kind analysis_kind not null default 'flatness';
```

기본값이 'flatness'라 기존 행과 코드는 그대로 동작한다.

### 3.2 현재 분석 유니크 인덱스 재정의

```sql
-- 기존: create unique index analyses_current on analyses(scan_id)
--         where is_current and deleted_at is null;
drop index analyses_current;
create unique index analyses_current on analyses(scan_id, kind)
  where is_current and deleted_at is null;
```

이렇게 하지 않으면 구배 분석이 평활도 분석을 밀어낸다.

### 3.3 기준 조회 함수 확장

`fn_resolve_criteria(site_id, surface)`에 `kind` 인자를 추가한다. 기존 호출부가
깨지지 않도록 기본값 `'flatness'`를 준다.

### 3.4 구배 기준 thresholds 형태

`criteria.thresholds`는 jsonb 배열 제약(`jsonb_typeof = 'array'`)이 걸려 있으므로
그 안에서 담는다.

```json
[{
  "use": "주차장 배수",
  "design_pct": 2.0,
  "pass_pct": 0.5,
  "re_pct": 1.5,
  "dir_pass_deg": 30
}]
```

- `design_pct`: 설계 구배(%)
- `pass_pct`: 적합으로 볼 크기 편차 한계
- `re_pct`: 이를 넘으면 재시공
- `dir_pass_deg`: 적합으로 볼 방향 편차 한계(도)

시드할 용도는 주차장 배수·욕실 바닥·옥상 슬래브·실내 평바닥 4종으로 시작한다.

**구체적 수치는 이 문서에서 정하지 않는다.** 임의로 지어내면 판정 전체가 근거
없는 값 위에 서게 된다. 구현 단계에서 각 용도의 설계 구배를 출처와 함께 조사해
`criteria.source_text`에 적고, 원문 대조 여부를 `docs/criteria-sources.md`와 같은
방식으로 표기한다. 세부과업 1에서 판정 기준 11종의 **원문 대조가 0건**(2차 출처
교차검증만)이었던 전례가 있으므로, 대조하지 못한 항목은 그렇다고 명시한다.

### 3.5 판정 파라미터

배수구 위치는 기존 `analyses.params jsonb`에 넣는다. 마이그레이션이 필요 없다.

```json
{ "drain_points": [{ "x": 3.2, "y": 5.1 }] }
```

### 3.6 정합 이력

```sql
create table registrations (
  id uuid primary key default gen_random_uuid(),
  source_scan_ids uuid[] not null,
  correspondences jsonb not null,   -- [{a:{x,y,z}, b:{x,y,z}}, ...]
  transform jsonb,                  -- 4x4 행렬
  rmse_mm double precision,
  iterations int,
  status text not null default 'awaiting_points',
  error_text text,
  result_scan_id uuid references scans(id),
  created_by uuid references profiles(id),
  created_at timestamptz not null default now()
);
```

정합 RMSE는 과업지시서 12쪽이 요구하는 "평면 피팅 오차 검증 데이터"에 대응한다.

### 3.7 보고서 소프트 삭제

```sql
alter table reports add column if not exists deleted_at timestamptz;
```

**발행본 불변 트리거를 함께 손봐야 한다.** 현재 `fn_reports_finalized_guard`는
`before update`에서 내용 컬럼 변경을 막는데, 소프트 삭제도 UPDATE이므로 잠금 대상
목록에 `deleted_at`을 넣지 않아야 발행본을 지울 수 있다. `gen_status`를 열어 둔
것과 같은 이유다. DELETE는 지금도 트리거가 막지 않는다.

### 4.2 구배 산출

서브셀 격자(기본 5cm)는 평활도와 공유하고 집계 단위만 2m로 바꾼다. 2m 셀 하나가
40×40 서브셀이다.

**셀별 평면 피팅은 원점군이 아니라 서브셀 중앙값에 한다.** 이유는 셋이다.

1. 노이즈가 중앙값 단계에서 이미 걸러진다
2. 점 밀도 불균일의 영향이 사라진다. 원점군에 그대로 피팅하면 스캐너에 가까워
   점이 빽빽한 구역이 평면을 끌어당긴다. 서브셀 중앙값은 면적당 균등하다
3. 계산량이 수천분의 1이다

산출값은 평면 `z = a·x + b·y + c`에서 다음과 같이 얻는다.

- 구배 크기(%) = `sqrt(a² + b²) × 100`
- 내리막 방향(rad) = `atan2(-b, -a)`. **`(a, b)`는 오르막 방향이므로 부호를 뒤집는다.**
  물은 내리막으로 흐르므로 배수 방향 판정은 내리막 기준이다. `atan2(b, a)`를 그대로
  쓰면 모든 방향 판정이 180도 뒤집혀 정상 배수가 역구배로 나온다
- 피팅 잔차 RMSE
- 기울기 표준오차 (4.3 참고)

### 4.3 셀별 불확도

평활도는 전역 상수 `U`를 썼고, 그 탓에 벽면 기준 4종 중 3종이 U=8mm에서 적합
판정 자체가 불가능해지는 문제가 있다(백로그 티켓 47). 구배는 그럴 필요가 없다.
최소제곱 평면 피팅이 기울기 계수의 표준오차를 직접 준다.

```
se(기울기) ≈ 잔차 RMSE / (sqrt(N) · sd(좌표))
```

셀마다 점 개수와 잔차가 다르므로 불확도도 셀마다 다르게 나온다. 데이터가 좋은
셀은 좁은 불확도로 단정하고, 나쁜 셀만 경계로 빠진다.

### 4.4 정합

- 입력: 두 점군 + 대응점 3쌍 이상
- 1단계: Umeyama/Kabsch로 강체 변환을 닫힌 형태로 계산(축척 고정)
- 2단계: point-to-plane ICP로 정밀화. 대응 탐색은 SciPy `cKDTree`
- 수렴: 직전 반복 대비 RMSE 변화율 `< 1e-4`, 또는 최대 반복 50회 도달
- 성공 임계: 최종 RMSE `≤ 2mm`. 요구 정밀도 ±5mm보다 충분히 작게 잡는다
- 출력: 4×4 변환행렬, 최종 RMSE, 반복 횟수, 수렴 여부

대응점 클릭은 화면 해상도 수준(10cm/픽셀이면 ±5cm)이므로, 요구 정밀도 ±5mm를
맞추려면 ICP 단계가 반드시 필요하다.

## 5. 판정 규칙

### 5.1 등급

평활도의 4등급을 그대로 쓴다. 같은 스캔에 두 분석 결과가 나란히 뜨므로 색과
어휘가 다르면 혼란스럽다.

| 등급 | 구배에서의 의미 |
|---|---|
| 적합 | 크기·방향 모두 허용 안 |
| 경계 | 불확도 폭이 허용 경계를 걸쳐 단정 불가 |
| 보수 | 허용을 벗어났으나 국소 보정으로 해결 가능 |
| 재시공 | 편차가 매우 크거나 역구배 |

### 5.2 판정 절차 (셀 단위)

기호: `g` = 실측 구배(%), `u` = 셀별 구배 불확도(%, 4.3의 표준오차를 %로 환산),
`d = |g − design_pct|`, `θ` = 실측 방향과 기대 방향의 각도 차.

기대 방향은 셀 중심에서 **가장 가까운 배수구 점**을 향하는 방향이다. 배수구가
지정되지 않으면 방향 판정(3·4번)을 건너뛴다.

1. **판정 불가 걸러내기.** 유효 서브셀이 10개 미만이면 평면이 수치적으로 결정되지
   않으므로 제외한다. 또한 `u > pass_pct`이면 그 셀은 애초에 적합·부적합을 가릴
   해상도가 없으므로 제외한다. 서브셀이 적거나 잔차가 크면 `u`가 커지므로 이
   한 조건이 "점 부족"과 "요철 심함"을 함께 처리한다. 제외된 셀은
   `coverage_pct`에서 빠지고 "구배 신뢰 불가" 경고를 남긴다
2. **역구배 우선.** `θ > 90°`이면 물이 설계와 반대로 흐르므로 크기와 무관하게
   **재시공**이다. 여기서 판정을 끝낸다
3. **재시공.** `d − u > re_pct` → 재시공
4. **적합.** `d + u ≤ pass_pct` 이고 `θ ≤ dir_pass_deg` → 적합
5. **보수.** `d − u > pass_pct` 이거나 `θ > dir_pass_deg` → 보수
6. **경계.** 위 어디에도 확정적으로 걸리지 않는 셀. 불확도 폭이 허용 경계를
   걸쳐 단정할 수 없는 경우다

`u`를 더하고 빼는 방향에 주의한다. 적합은 불확도를 감안해도 확실히 안쪽일 때만
주고(`d + u`), 재시공은 불확도를 감안해도 확실히 바깥일 때만 준다(`d − u`).
그 사이는 경계로 남긴다.

### 5.3 보정 방향

실측 벡터에서 설계 벡터를 빼면 보정 벡터가 나온다. 이를 %로만 보여주면 시공자가
쓸 수 없으므로 **높이차로 환산한다.** 2m 셀에서 구배 0.5% 차이는 양단 높이차
10mm다. 결과표에는 "북동쪽 끝을 10mm 낮춤" 형태로 적고, 지도에는 화살표로 그린다.

### 5.4 통계

과업지시서 명시 항목을 그대로 낸다. 구간별 평균편차·표준편차·최대편차이며,
"구간"은 기존 구역화(`core/zones.py`) 결과를 쓴다. 레벨이 다른 구역은 설계 구배도
다를 수 있으므로 구역별로 나눠 낸다.

## 6. 정합 흐름

### 6.1 precheck를 살려 높이 뷰를 만든다

현재 `handle_precheck`는 `unit_scale` 유무만 보고 상태를 승격한다. 여기서 **위에서
내려다본 높이 뷰 PNG**를 만들면 세 가지가 한 번에 풀린다.

- 정합: 대응점을 찍을 화면이 생긴다
- 배수구 지정: 분석 전에 배수구를 정할 수 있다
- 단위 확정 화면: 지금은 파일명과 라디오 버튼만 보여줘 사용자가 무엇을 확정하는지
  알 수 없다. 그림이 있으면 "이 방이 8m인가 80cm인가"를 눈으로 판단할 수 있다

단위 확정 전이라 축척을 모르지만 상대 좌표로 그리면 되고, 오히려 범위 판단에
도움이 된다.

### 6.2 단계

1. 두 스캔을 각각 업로드(기존 경로 그대로). precheck가 각각 높이 뷰를 만든다
2. 정합 시작 → `registrations` 행 생성(`status='awaiting_points'`)
3. 두 뷰를 나란히 놓고 번갈아 클릭해 대응점 쌍을 만든다. 최소 3쌍, 권장 4쌍 이상.
   Z는 클릭한 XY 위치의 서브셀 중앙값에서 읽는다
4. 정합 잡 실행 → Umeyama → ICP → 변환행렬·RMSE
5. RMSE가 납득되면 병합 스캔 생성

### 6.3 병합 산출물은 서브셀 중앙값 점군

두 문제를 동시에 푼다.

**중첩 영역 보완**(과업지시서 명시): 중첩 서브셀에 두 소스의 점이 함께 들어가고
중앙값이 뽑히므로, 별도 가중치 없이 이상치에 강하게 통합된다.

**파일 크기**: 두 점군을 그대로 이어붙이면 Storage 버킷의 50MB 상한에 걸린다.
5cm 서브셀 중앙값이면 600 m² 바닥이 약 24만 점, 3MB 수준이다. 분석은 어차피
서브셀 중앙값만 쓰므로 **결과가 동일하다.**

원본 두 개는 그대로 남고 `registrations`가 소스와 결과를 잇는다.

### 6.4 잡 타입

기존 잡 타입은 `precheck`·`analyze`·`import`·`report` 4종이다. 다음이 더해진다.

| 잡 타입 | 하는 일 | 무게 |
|---|---|---|
| `analyze` (kind='slope') | 점군 → 2m 셀 구배 벡터 산출 | 무거움 |
| `slope_judge` | 산출된 셀 벡터 + 배수구 위치 → 판정·산출물 갱신 | 가벼움(점군 미열람) |
| `register` | 대응점 → Umeyama → ICP → 병합 스캔 생성 | 무거움 |

`precheck`의 계약이 바뀐다. 지금은 상태 승격만 하지만, 앞으로는 **높이 뷰 PNG를
만들어 Storage에 올린 뒤** 상태를 승격한다. 기존 스캔은 이 그림이 없으므로 화면은
그림이 없을 때를 견뎌야 한다.

`analyze` 잡은 `analyses.kind`를 보고 평활도·구배 파이프라인으로 분기한다. 잡
타입을 새로 만들지 않는 이유는, 워커가 이미 `analysis_id`로 행을 읽으므로 종류가
그 안에 들어 있기 때문이다.

## 7. 대시보드 화면

### 7.1 분석 시작

스캔 상세에 "평활도 분석" / "구배 분석" 두 버튼. 같은 스캔에 둘 다 돌릴 수 있고
`analyses.kind`가 다르므로 서로를 밀어내지 않는다. 결과 화면에 탭으로 나란히 붙는다.

### 7.2 구배 결과 화면

평활도 화면의 구조를 따른다.

- 구배 크기 히트맵(4등급 색) + 방향 화살표 오버레이
- 상단에 "배수구 위치를 클릭하세요" 안내. 클릭하면 재판정 잡이 돌고 갱신된다
- 결과표: 셀별 구배 %, 설계 대비 편차, 보정 높이차(mm), 등급
- 구역별 통계

**역구배 셀은 색만으로 드러나지 않는다.** 크기가 정상이면 초록인데 물은 반대로
흐른다. 화살표를 굵게 하고 결과표에 별도 표시한다.

### 7.3 재판정

분석은 배수구 없이 한 번만 돌려 셀별 구배 벡터를 산출물로 남긴다. 배수구를
클릭하면 그 산출물만 읽어 판정을 다시 한다(점군을 읽지 않으므로 수 초).

판정 로직을 브라우저에서 미리 계산해 즉시 보여주는 방식은 **의도적으로 피한다.**
판정이 파이썬 엔진과 브라우저 두 곳에 생기고, 세부과업 1에서 같은 종류의 이중화가
실제로 어긋난 전례가 있다.

### 7.4 정합 화면

두 스캔을 나란히 놓고 번갈아 클릭한다. 찍은 쌍이 목록으로 쌓이고 3쌍 이상이면
"정합 실행"이 활성화된다. 결과 RMSE를 보여주고, 납득되면 "병합 스캔 만들기"로
확정한다. RMSE가 나쁘면 대응점을 다시 찍게 한다.

### 7.5 단위 확정 화면

precheck가 만든 높이 뷰를 표시한다.

### 7.6 보고서 삭제

보고서 목록과 상세 양쪽에 둔다. 소프트 삭제이며 목록에서 거른다. 발행본을 지울

## 9. 테스트·검증

### 9.1 구배 산출

합성 데이터로 게이트를 건다. **알려진 구배**(예: 2.0%, 방향 45°)의 평면을 생성하고
노이즈를 주입한 뒤 산출값을 대조한다.

- 과업지시서 요구 분석 오차율 **±5% 이내**를 게이트로 건다
- 노이즈 수준별(0.5·1·2·5mm)로 산출 오차를 실측해 기록한다. 구배는 2m 셀에
  수천 개 서브셀을 피팅하므로 평활도보다 노이즈에 훨씬 강할 것으로 보이나,
  **수치는 실측으로 확인한다**

### 9.2 판정

- 역구배 케이스: 크기는 설계와 같고 방향만 180° 반대 → 재시공이 나와야 한다
- 경계 케이스: 편차가 허용 경계에 불확도 폭으로 걸치는 셀 → 경계
- 배수구 미지정 시 방향 판정을 건너뛰는지

### 9.3 정합

알려진 강체 변환(회전 + 평행이동)을 걸고 노이즈와 부분 중첩을 준 뒤, 정합이 그
변환을 오차 안에서 복원하는지 확인한다. 실물 데이터 없이도 정확도를 증명할 수 있다.

- **복원 게이트**(노이즈 1mm, 중첩 50%): 회전 오차 `≤ 0.1°`, 평행이동 오차 `≤ 1mm`.
  요구 정밀도 ±5mm보다 충분히 작게 잡는다
- 대응점에 ±5cm 오차(화면 클릭 정확도 수준)를 준 상태에서 ICP가 위 게이트까지
  회복하는지. **이것이 반자동 정합의 핵심 가정이므로 반드시 검증한다**
- 중첩이 거의 없는 경우(10% 미만) 성공을 가장하지 않고 실패로 끝나는지

#### 9.3.1 설계 결정 F1 — 위 평행이동 게이트는 달성 불가능함이 실측으로 확인되어 교체했다

> 위 원 게이트는 기록으로 남긴다. 지운 것이 아니라 **교체**했다. 단계 F Task 2에서
> 원 게이트 자신의 조건(노이즈 1mm, 대응점 ±5cm)으로 실측한 결과가 아래다.
>
> **정확히 무엇이 불가능한가.** 대응점에 클릭 오차가 없으면 원 게이트는 그대로
> 성립한다(실측 회전 0.00066°, 평행이동 0.126mm — 아래 G0). 불가능해지는 것은
> 여기에 **±5cm 클릭 오차**가 더해질 때다. 즉 알고리즘의 한계가 아니라
> "화면 클릭으로 대응점을 찍는다"는 입력 조건의 한계다.

**원인은 버그가 아니라 구조적 퇴화다.** 수평 평면은 면내 평행이동 2자유도와 yaw에
대해 정보를 주지 않는다 — 평면을 자기 위에서 밀어도 점군이 그대로라 ICP가 그 방향의
잔차를 줄일 수 없다. 사전조사 실측(단계 F 착수 전, 브리프 기록):

| 픽스처 | 초기 면내 오차 | ICP 후 면내 | ICP 후 z |
|---|---|---|---|
| 무작위 순수 평면 | 169mm | **160.0mm** | −0.000mm |
| 범프+단차 | 170mm | 149.4mm | 0.756mm |
| 바닥+벽 2면 | 108mm | 135.5mm | −1.783mm |
| 대조: 지터 0 | 0mm | **0.002mm** | −0.001mm |
| 중첩 10% | 129mm | 2713mm | −2.164mm |

지터 0 대조군이 0.002mm를 내는 것이 **ICP 자체는 멀쩡함**을 증명한다.

**그런데 이 실패는 목적상 거의 무해하다.** 면내 오차 `d`가 병합 서브셀 중앙값 z에
주는 영향은 `국소 경사 × d`뿐이다. 구배 2%에서 `d`=150mm면 3.00mm로 요구 정밀도
±5mm 안이다. 그래서 **대리 지표(면내 mm) 대신 진짜 계약(중첩 서브셀 중앙값 z 불일치)**
을 게이트로 삼는다.

**교체 게이트와 실측값** (`engine/tests/test_registration.py`). 아래는 **전부 표본
독립 픽스처**에서 잰 값이다 — 두 스캔이 같은 바닥을 서로 다른 점으로 표본한다:

| # | 게이트 | 조건 | 기준 | 실측 |
|---|---|---|---|---|
| G0 | **원 게이트 유지** — 회전 + 평행이동 | 노이즈 1mm, 클릭 오차 0 | ≤0.1° / ≤1mm | **0.00066° / 0.126mm** |
| G1 | z 평행이동 오차 | 노이즈 1mm + 클릭 오차 ±5cm | ≤1mm | **0.0080mm** |
| G2 | 중첩 서브셀 중앙값 z 불일치 | 노이즈 1mm + 클릭 오차 ±5cm | ≤ 노이즈+1mm = 2mm | **0.6629mm** |
| G3 | §4.4 최종 RMSE (point-to-plane) | 노이즈 1mm + 클릭 오차 ±5cm | ≤2mm | **1.047mm** |
| G4 | 저중첩은 실패로 끝난다 | 실제 중첩 2.57% | `converged=False` + 사유에 "중첩" | **불성립 보고 확인** |

부가 실측: 중첩 50%(§9.3 명시 조건) z 0.0079mm·RMSE 0.998mm·수렴. 바닥+벽 장면
RMSE 1.558mm·수렴. 유령층 15% z 0.0282mm·수렴.

**회전 오차는 교체 게이트에서 빠졌다 — 원 게이트를 만족하지 못한다.** 클릭 오차
±5cm에서 실측 yaw 오차는 **0.41283°**로 원 게이트 `≤0.1°`의 **4.1배**다. 회전도
평행이동과 같은 면내 퇴화의 일부다. z만 살아남는다.

**ICP가 클릭 오차를 얼마나 회복하는가** — §9.3 원문은 "ICP가 위 게이트까지 회복하는지"를
핵심 가정으로 두는데, 실측하면 **그 가정은 z에 대해서만 참이다**:

| 단계 | yaw | 면내 | z |
|---|---|---|---|
| 초기 Umeyama (대응점만) | 0.46214° | 51.720mm | 0.264mm |
| ICP 후 | 0.41283° | 44.656mm | 0.008mm |
| 개선 | **11% 감소** | **14% 감소** | **33배 개선** |

즉 ICP는 면내·회전을 거의 못 고치고 z만 회복한다. 면내 오차는 게이트를 걸지 않는다.

**적용 범위 — 구배가 붙으면 z 게이트가 깨진다.** 면내 오차가 z에 새는 양은
`국소 경사 × 면내 변위`다. 위 픽스처는 국소 경사 median 0.10%로 사실상 평탄이라
구배 램프를 얹어 따로 실측했다(클릭 ±5cm):

| 구배 | z 오차 | 판정 |
|---|---|---|
| 0% | 0.008mm | G1 성립 |
| 1% | 0.309mm | G1 성립 |
| 2% | 0.611mm | G1 성립 |
| **3%** | **0.883mm** | **G1 성립 (상한)** |
| 3.5% | 1.062mm | G1(≤1mm) 붕괴 |
| 5% | 1.477mm | G1 붕괴 |
| **15.0%** | **4.841mm** | **±5mm 안 (상한)** |
| 15.5% | 5.056mm | ±5mm 초과 |
| 20% | 7.037mm | ±5mm 초과 |

**적용 범위: G1(z ≤1mm)은 구배 ≤3%, 요구 정밀도 ±5mm는 구배 ≤15%.**

**세부과업 4는 구배 측정 용역이므로 이 제한을 정면으로 읽어야 한다.** 통상
바닥 배수구배 1~2%는 범위 안이지만, 주차장 램프급(10~20%)은 G1 범위 밖이고
15.5%부터는 요구 정밀도 ±5mm도 넘긴다. 위 모든 구간에서 `converged=True`가
나오므로 **엔진은 이 열화를 스스로 보고하지 못한다** — 급구배 구간이 포함된
현장은 정합 정확도를 별도로 검토해야 한다.

**부수 발견 1 — 픽스처 교락.** "두 점군의 점이 1:1로 동일한"(`b = 강체변환(a)`)
픽스처는 최근접점 탐색이 늘 같은 점을 찾아버려, 바닥을 **완전 평면으로 바꿔도
자릿수까지 똑같이 통과한다**. 대조 실측 — 완전 평면에서 면내 오차가 1:1 동일점이면
**0.026mm**, 표본 독립이면 **47.15mm**다. 평면은 면내 정보를 원리적으로 갖고 있지
않으므로 0.026mm는 표면이 아니라 점 동일성에서 나온 값이다. 그런 픽스처를 쓰는
테스트는 표면 관련 결함을 전혀 검증하지 못한다.

**대응:** 모든 정합 테스트를 표본 독립 픽스처(`_scan_pair`)로 바꿨고, 되돌리지
못하도록 회귀 가드 두 개를 뒀다 — `test_scan_pair_fixture_does_not_share_sample_points`
(참값 정렬 시 최근접점 거리 중앙값 > 5mm), `test_identical_point_fixture_recovers_
in_plane_even_on_a_featureless_plane`(위 0.026mm vs 47.15mm 대비를 고정). 픽스처를
1:1로 되돌리면 두 가드가 먼저 깨진다(변이 실험으로 확인).

**부수 발견 2 — `RMSE ≤ 2mm`는 point-to-plane 잔차 기준이라야 성립한다(해소됨).**
point-to-point 잔차에는 **표본 간격의 절반 수준 하한**이 있다. 두 스캔이 같은 표면을
서로 다른 점으로 표본하면 접선 방향 어긋남이 잔차에 그대로 섞이기 때문이다. 표본
간격 5cm에서 실측 point-to-point RMSE는 **19.50mm**로, 정합이 정확한데도(z 0.008mm)
게이트를 못 넘는다. 그것은 정합 품질이 아니라 **격자 해상도의 그림자**다. 실제 병합
입력이 서브셀 중앙값 점군(§6.3, 5cm 격자)이므로 현장에서 모든 정합이 실패로 보고될
위험이었다.

**해소:** `rmse_m`을 §4.4 원문대로 **point-to-plane 잔차**(대응쌍 변위의 국소 법선
방향 성분)로 계산하도록 바꿨다. 접선 방향 이산화가 섞이지 않아 하한이 없고, 같은
정합에서 **1.047mm**로 게이트를 통과한다(위 G3). 바닥에서는 법선이 대략 +z이므로 이
잔차는 사실상 `|Δz|`가 되는데, 그것이 이 용역이 실제로 재고 싶은 양이다.

**구현 이탈 기록 — 잔차를 두 가지로 나눠 쓴다.**

| 용도 | 잔차 | 근거 |
|---|---|---|
| 대응 탐색·최소화 | point-to-point (Umeyama) | 단계 F 브리프 지시. 변환 정확도는 위 표로 검증됨 |
| **수렴 판정** (`rmse_rel_tol`) | point-to-point | 최소화하는 그 양을 봐야 단조 감소가 보장되고 판정이 흔들리지 않는다 |
| **보고값 `rmse_m`·성공 임계** | **point-to-plane** | §4.4의 `≤2mm`가 전제한 양. 하한이 없다 |

즉 §4.4의 "point-to-plane ICP"에서 **잔차 정의는 지켰고 최소화 방식만 point-to-point**
다. 법선은 `cKDTree` k=16 근방 공분산의 최소 고유벡터로 추정한다. 법선을 상수
`[0,0,1]`로 가정하면 바닥에서는 티가 안 나지만(바닥 전용 테스트는 전부 통과) 벽에서
90° 틀려서 RMSE가 1.558mm → **7.42mm**로 튄다 — 바닥+벽 장면 테스트로 고정했다.

#### 9.3.2 point-to-plane 전환의 대가 — 수평 오정합을 원리적으로 못 본다 ★

위 전환으로 얻은 것만 적으면 안 된다. point-to-plane 잔차는 변위의 **법선 방향
성분만** 세므로, 수평면 위에서 **접선 방향으로 밀린 어긋남에 완전히 무감각하다**:

| 바닥 | 수평 어긋남 | point-to-plane | point-to-point | 게이트 |
|---|---|---|---|---|
| 범프 | 0mm | 1.004mm | 19.45mm | 통과 |
| 범프 | 200mm | 2.865mm | 19.95mm | 탈락 |
| 범프 | 1000mm | 7.156mm | 21.69mm | 탈락 |
| **완전평면** | **1000mm** | **1.004mm** | 20.25mm | **통과** |
| **완전평면** | **3000mm** | **1.006mm** | 20.88mm | **통과** |

범프가 있는 바닥에서는 200mm부터 게이트가 잡는다. 그러나 **이 용역의 대상은 ±5mm
평탄 바닥**이므로 현장은 아래 두 행에 가깝다 — 3m 어긋난 정합도 RMSE 1.006mm로
성공 보고된다. point-to-point로 되돌려도 대안이 못 된다(0mm 19.45mm → 3000mm
20.88mm, 판별력 7%이고 어차피 전부 탈락시킨다). **정보가 데이터에 없다.**

**정식 경로에서도 막지 못한다(실측).** 아래 완화 조치를 다 넣은 뒤에도, 완전 평면에서
대응점을 **통째로 수평 3m 틀리게** 찍으면 `register_clouds`가 이렇게 답한다:

```
면내 오차 3.000m | rmse_m 1.008mm | p2p/표본간격 0.68 | converged=True | failure_reason=None
```

세 게이트(RMSE·중첩·발산)가 전부 통과한다. **완화 조치는 이 트리거를 막지 못한다.**

**완화 조치 4종.**

1. **대응점 기하 검사**(§8 구현, 아래 9.3.3) — 퇴화 배치를 입구에서 막는다.
   단, 위처럼 **일관되게 어긋난 정상 배치**는 막지 못한다
2. **발산 가드** — `point_rmse_m > 1.5 × 표본 간격`이면 실패. 표면 **밖**으로 벗어난
   자세를 잡는다(가장자리 밖 0.2~0.4m 띠는 point-to-plane 0.000mm·중첩 0.800으로
   두 게이트를 통과하지만 point-to-point가 1.60배로 튄다). ★ 탐지 측 여유가
   **6.4%뿐**이다(회귀 픽스처 1.596 vs 임계 1.5) — 정상 측 여유(0.70 대비 2.1배)와
   비대칭이므로 임계를 올리면 탐지가 먼저 죽는다
3. **감도 프로브 `horizontal_sensitivity`** — 아래 9.3.5. **사각을 막지는 못하지만
   사각임을 보고한다.** 위 3m 사례에서 감도 0.994를 낸다
4. **`point_rmse_m`·`sample_spacing_m` 보고** — 잔차를 교차 확인할 수 있게 실어 보낸다

**남는 위험(미해소).** 완전 평면에서 대응점을 일관되게 수평으로 잘못 찍으면 어떤
잔차 지표로도 **차단**되지 않는다. §7.4 화면은 RMSE만 보여주지 말고 **정합 후 두
점군을 겹쳐 그린 그림**과 `horizontal_sensitivity` 경고를 함께 제시해야 하며,
§8의 자동 방어선을 RMSE 단독으로 두면 안 된다.

#### 9.3.5 감도 프로브 — "수평 정보가 데이터에 있는가"를 직접 잰다

정합 결과를 수평으로 ±10cm 밀어 보고 point-to-plane 잔차가 오르는 비를 잰다
(±x·±y 4방향 중 **최솟값** = 최악 방향). KD트리·법선이 이미 있어 추가 비용은
질의 4회뿐이다. 실측:

| 장면 | RMSE₀ | 감도(최악 방향) | 판정 |
|---|---|---|---|
| **완전 평면(사각)** | 1.004mm | **1.000** | **검증 불가** |
| 바닥+벽 | 1.551mm | 1.248 | 정상 |
| 범프 바닥 | 1.004mm | 1.710 | 정상 |
| 구배 1~10% 램프 | 1.004mm | 1.86~1.87 | 정상 |
| 복도 150m×2.5m | — | 1.369 | 정상 |

임계 `HORIZONTAL_SENSITIVITY_MIN = 1.1`이 유일한 사각(완전 평면)만 걸러낸다.

**실패로 처리하지 않는다.** ±5mm 평탄 바닥이 이 용역의 정상 대상이라 전부 막으면
기능이 성립하지 않는다. 대신 §7.4가 이 값으로 **"수평 방향 검증 불가"를 경고**하고
겹친 그림을 함께 보여야 한다. `rmse_m`만으로는 두 장면이 구분되지 않는다는 점이
핵심이다 — 완전 평면과 범프 바닥의 RMSE는 둘 다 1.004mm로 같다.

#### 9.3.3 §8 대응점 거부 구현 — 개수만 세면 안 된다

§8 원문의 "공선 → 정합 거부"를 구현했다. 개수 검사만으로는 부족하다는 실측:

**판별은 절대량으로 한다 — 무차원 비는 스케일에 끌려간다.**

`sv1/sv0`(2번째/1번째 특이값 비)는 무차원이라 현장이 길수록 같은 물리적 폭에서
작아진다. 그 규칙은 실효적으로 "대응점 배치 종횡비"를 재게 되어, **물리적으로 더
좋은 배치를 거부하고 더 나쁜 배치를 통과시킨다**:

| 대응점 배치 | sv1/sv0 | **측방 RMS 퍼짐** | 가드 없이 정합하면 | 판정 |
|---|---|---|---|---|
| 정상 4점 (8m×6m) | 0.6695 | 1.925m | 면내 44.7mm | 통과 |
| **복도 150m×2.5m** | **0.0163** | **1.001m** | **면내 37.5mm (더 좋다)** | **통과해야 한다** |
| 복도 60m×2.0m | 0.0324 | 0.801m | 면내 30.7mm | 통과해야 한다 |
| 좁은 띠 중첩 4점 | 0.0552 | 0.108m | 정상 | 통과해야 한다 |
| 작은 방 0.8m×0.6m | 0.7224 | 0.236m | — | 통과해야 한다 |
| 6m 거리에 12cm 편차 | 0.0231 | 0.057m | — | 경계 |
| 완전 공선 3점 | **0.0000** | **0.000m** | 통과(사유 없음) | **거부** |
| 근접 3점(2cm 안) | 0.9808 | **0.008m** | **초기 Umeyama가 yaw 89°·면내 5.3m** | **거부** |

근접 3점은 **공선성 지표로는 정상보다 좋아 보인다**(0.98 > 0.67). 옳은 질문은
"측방 퍼짐이 **클릭 오차 대비** 충분한가"다. 회전 불확도 ≈ 클릭오차 / 측방퍼짐이다.

**게이트: 측방 RMS 퍼짐(`sv1/√N`) ≥ 클릭 오차 5cm.** 이것 하나만 게이트이고,
특이값 비는 사유 문구를 "공선"으로 쓸지 고르는 데만 쓴다. 최대 거리 절대 기준
(이전 1.0m)은 **없앴다** — 0.8m×0.6m 방·계단참(퍼짐 0.791m)이 정합 불가능해졌었다.

`ValueError`와 한국어 사유로 거부한다(기존 "3쌍 미만"과 같은 방식). 근접 3점은
초기 해가 이미 틀어져 ICP가 못 고치므로 **가드는 대응점 단계에 있어야 한다**.

#### 9.3.4 `overlap_ratio`의 정의 주의 — `trim_ratio`가 상한이다

`overlap_ratio = 쓴 쌍 수 / len(src)`인데 trimmed ICP가 항상 하위 `trim_ratio`만
쓰므로 **100% 겹쳐도 최댓값이 0.8**이다(기본 `trim_ratio=0.8`). 따라서 §9.3의
"중첩 10% 미만 거부"는 실제로는 **참 중첩 12.5% 미만**을 거른다.

마이그레이션 012가 이 값을 `registrations.overlap_ratio`로 저장하고 §7.4가 사용자에게
보여주므로, **화면에 참 중첩으로 표시하려면 `trim_ratio`로 나눠야 한다.** 값 자체는
Task 4가 이미 이 API로 구현 중이라 바꾸지 않았다 — 정의를 문서로 고정한다.

크다.** 다음 순서로 나눠 각각이 독립적으로 동작하는 상태로 끝나게 한다.

| 단계 | 내용 | 끝났을 때 |
|---|---|---|
| A | 보고서 삭제 | 세부과업 4와 무관한 별건. 작아서 먼저 털고 간다 |
| B | 엔진 구배 산출 + CLI | 점군에서 2m 셀 구배가 나오고 CLI로 확인된다 |
| C | 마이그레이션 007 + 워커 분기 + 기준 시드 | 대시보드에서 구배 분석을 돌릴 수 있다 |
| D | 구배 결과 화면 + 배수구 클릭 + 재판정 | 판정과 보정 방향까지 화면에서 완결된다 |
| E | precheck 높이 뷰 + 단위 확정 화면 개선 | 정합 UI의 전제가 갖춰진다 |
| F | 정합 엔진 + 정합 화면 + 병합 스캔 | 멀티 소스 정합이 동작한다 |
| G | 스캔 가이드라인 문서 + 용역 보고서 갱신 | 과업지시서 문서 성과물이 채워진다 |

E가 F보다 앞인 이유는 대응점 클릭 화면이 높이 뷰에 의존하기 때문이다. B가 C보다
앞인 이유는 엔진 산출 형태가 확정돼야 DB 스키마와 산출물 규약을 정할 수 있기
때문이다.
