# 정밀 편차맵(10cm 보조 시각화) 설계 스펙

> **정본 스펙과의 관계**: 본 문서는 `docs/superpowers/specs/2026-07-27-flatness-dashboard-design.md`(이하 정본)를
> **대체하지 않는 추가 기능 스펙**이다. 정본 §5.1 항목 9(산출물) 목록에 파일 2종(`deviation.png`, `deviation_wall{n}.png`)을
> **추가**할 뿐, 정본의 판정식(§4.2)·셀 판정과 stats 필수 필드(§5.1 항목 5~7)·히트맵 5색 규약·보고서 구성(§8)은 한 글자도 바꾸지 않는다.
> 데이터 계약 정본은 `docs/contracts/stats-schema.md`이며, 본 기능이 추가하는 stats 키도 그 문서에 반영한다.

## 1. 배경과 문제

현재 결과 화면과 보고서의 시각자료는 **판정 히트맵**(`heatmap.png` / `heatmap_wall{n}.png`)이다. 이 그림은 1m 판정 셀 단위로
4등급 + 판정 불가를 이산 색으로 칠한다. 판정 결과를 전달하는 데는 정확하지만, 셀 하나가 1m²라 **결함의 실제 모양과 크기**가
보이지 않는다. 30cm짜리 함몰이든 90cm짜리 완만한 처짐이든 같은 색 사각형 하나로 뭉개진다. 현장에서 "어디를 얼마나 갈아야
하는가"를 판단하려면 등급이 아니라 편차의 공간 분포가 필요하다.

3D 프리뷰(`preview3d.png`)가 이 갈증을 일부 풀지만 등각 산점도라 위치를 자로 재기 어렵고, 시점에 가려지는 영역이 생긴다.
따라서 **평면 도면과 같은 방식으로 원시 편차를 보여주는 2D 보조 시각화**를 추가한다.

## 2. 해상도 결정 근거 (실측)

데모 점군(8x6m, 점 간격 2cm)으로 후보 해상도를 실측했다.

| 후보 | 셀 채움률 | 판단 |
|---|---|---|
| 1cm | 0% | 서브셀 중앙값 필터의 최소 점 개수 3개 조건을 못 채워 전 셀이 NaN. 사용 불가 |
| 5cm | 100% (셀당 평균 6.3점) | 사용 가능하나 그림이 노이즈에 가깝고, 엔진 서브셀 해상도와 같아 정보가 중복 |
| **10cm** | **100%** | 채택. 5cm 서브셀 잔차를 2x2 평균 풀링해 얻으므로 **재계산이 없다** |

10cm를 택한 결정적 이유는 비용이다. 엔진은 이미 5cm 서브셀 잔차 배열(`build_zones()` 반환값 `residuals`, 벽은
`residual_grid()` 결과)을 판정 과정에서 만든다. 여기에 2x2 평균 풀링(NaN 무시) 한 번이면 10cm 격자가 나온다. 점군을 다시
읽지도, 평면을 다시 피팅하지도 않는다.

## 3. 산출 방식

`residuals`(5cm, NaN 포함, 단위 m)를 2x2 블록 평균으로 접는다. 블록 안의 유효값만 평균하고, 블록 전체가 NaN이면 결과도
NaN으로 남긴다(데이터가 없는 곳을 0mm로 칠하면 "평탄하다"는 거짓 정보가 된다). 격자 변 길이가 홀수면 NaN으로 패딩한 뒤
접는다. 풀링 배율은 `round(0.10 / subcell_m)`로 계산하므로 분석 파라미터 `subcell_m`이 기본값 0.05가 아니어도 목표
해상도가 유지된다.

풀링 결과에 1000을 곱해 mm로 바꾸고, `matplotlib.imshow`로 `origin="lower"`·`aspect="equal"`·`interpolation="nearest"`
렌더한다. NaN 셀은 마스크 처리해 회색(`#e8e8e8`)으로 칠한다.

## 4. 색상 스킴

**`RdYlGn_r` 발산 colormap, 0mm 중심, ±최대 절대편차 대칭 정규화**를 쓴다. 0mm는 연노랑, 융기(벽은 돌출) 방향은 붉게,
침하(벽은 함몰) 방향은 초록으로 간다. 부호 규약은 정본 §5.1 항목 7 그대로다(바닥 + = 융기 / - = 침하, 벽 + = 돌출 / - = 함몰).
컬러바 라벨에 이 규약을 함께 적는다.

이 선택에는 알아둘 긴장이 하나 있다. 판정 히트맵에서 초록은 "적합"인데, 편차맵에서 초록은 "깊은 침하"다. 같은 색이 두
그림에서 반대 뜻을 갖는다. 그럼에도 `RdYlGn_r`를 쓰는 이유는 (a) 이미 3D 프리뷰가 편차를 같은 colormap으로 칠하고 있어
**편차를 말하는 그림끼리는 색 언어가 일치**하고, (b) 발산 데이터에 순차 colormap을 쓰면 부호가 사라지며, (c) 데모 점군으로
시험 렌더해 결함 3개(함몰 2개·융기 1개)가 정확히 잡히고 배경은 노이즈만 옅게 보이는 수준임을 눈으로 확인했기 때문이다.
색 충돌은 팔레트가 아니라 **문맥 표기**로 해소한다: 편차맵에는 항상 컬러바(수치 축)와 "판정에 사용되지 않는 보조
시각화"라는 캡션이 붙는다. 판정 히트맵에는 컬러바가 없고 등급 범례가 붙으므로 두 그림은 범례만 봐도 구분된다.

완전 평탄면(합성 픽스처처럼 편차가 정확히 0)에서 `vmin == vmax`가 되어 정규화가 퇴화하는 것을 막기 위해 최대값에
0.5mm 하한을 둔다. 그림의 긴 변은 9인치로 고정해 넓은 바닥에서도 PNG 크기가 폭주하지 않게 한다.

## 5. 판정 무관성 (가장 중요한 제약)

이 기능은 **판정 파이프라인에 어떤 입력도 제공하지 않고, 어떤 출력도 바꾸지 않는다.** `evaluate_cells`·`grade_cells`·
직선자 스팬 계산·`build_stats`의 등급/수치 필드는 전부 그대로다. 편차맵은 이미 계산이 끝난 잔차 배열을 읽어 PNG 한 장을
더 쓰고, stats.json에 **파일명 목록 필드 하나**를 더할 뿐이다. 편차맵 생성이 실패하거나 건너뛰어져도 등급 결과는 동일하다.

이 원칙은 UI 문구로도 강제한다. 편차맵 탭과 보고서 캡션에는 "판정 등급 산출에는 사용되지 않으며, 등급은 1m 판정 셀
기준"이라는 안내를 함께 표시한다.

## 6. 산출물 파일명과 계약

| 파일 | 경로 | 조건 |
|---|---|---|
| `deviation.png` | 바닥 분석(`analyze_floor`) | 유효 잔차가 하나라도 있으면 생성 |
| `deviation_wall{n}.png` | 벽면 분석(`analyze_wall`) | `n`은 `wall_id`. **스킵된 벽은 파일이 없다(결번)** — 기존 `heatmap_wall{n}.png`와 동일 규약 |

stats.json에는 **`deviation_paths`(`string[]`, 바닥·벽 공통)** 를 추가한다. 값은 실제로 생성한 파일명만 순서대로 담으므로,
소비자는 결번을 신경 쓸 필요 없이 목록을 그대로 순회하면 된다(기존 `preview3d_paths`와 같은 형태·같은 사용법).
임포트 경로(`import_colab_csv`)는 이 키를 만들지 않으므로 소비자는 항상 "없으면 빈 목록"으로 다뤄야 한다.

## 7. 적용 범위 (4개 레이어)

1. **엔진**: `outputs/deviation.py` 신설(`render_deviation_map()`), `core/pipeline.py`의 `analyze_floor`·`analyze_wall`에서
   호출, `stats["deviation_paths"]` 기록
2. **계약 문서**: `docs/contracts/stats-schema.md` §2 조건부 키 표와 §6 산출물 파일 규약에 **추가만** 한다(기존 행 삭제·수정 금지)
3. **워커**: `report/assets.py`가 편차맵도 `reports/{id}/assets/{analysis_id}/`로 복사하고, 보고서 §4 시각자료에 표시.
   결번 처리는 기존 벽 히트맵과 동일하게 파일 존재를 가정하지 않는다
4. **대시보드**: 결과 화면에 "정밀 편차맵" 탭 추가(히트맵·3D 프리뷰·현장 사진 옆). 이미지는 기존 3D 프리뷰와 같은
   `/api/data` 경로로 서빙한다

## 8. 비범위 (YAGNI)

- 해상도 사용자 설정 UI 없음. 10cm 고정이다
- 임계선·등고선 표시 없음. 순수 연속 색상이다(임계 판단은 판정 히트맵의 역할)
- 히스토그램과 무관하다(보고서 전용 자산으로 이미 별도 존재)
- 인터랙티브 확대·셀 클릭 상세 없음(정적 PNG). 상호작용이 필요하면 히트맵 탭을 쓴다
- 임포트(Colab CSV) 경로에는 생성하지 않는다
