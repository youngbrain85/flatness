## 0. 범위: 세 갈래 중 1번

사용자 요청을 세 갈래로 나눈다. 갈래마다 스펙 → 계획 → 구현을 따로 돈다.

1. **이 스펙: 화면.** 대시보드 전체를 어두운 C안("스테이지")으로 바꾸고, 화면 구조를 현장 작업 공간으로 바꾼다. 대시보드만 바뀐다. 엔진·워커·DB·PDF 는 바뀌지 않는다.
2. **엔진 화면용 그림(다음 스펙).** 높이 그림·구배 지도의 어두운 판을 엔진이 따로 그린다. 정밀 편차맵은 엔진이 5cm 잔차 격자를 내보내고 대시보드가 직접 그리며, 표시 해상도 5·10·20cm 를 고른다(기본 5cm).
3. **판정 셀 크기 선택(그다음 스펙).** 히트맵 판정 셀 0.5·1·2m 를 고른다(기본 0.5m). 셀 크기에 따라 판정 수치와 보고서가 바뀌는 방법론 변경이라 따로 다룬다(실측: 같은 바닥이 1m 에서 48칸·보수 4·최대 14.86mm, 0.5m 에서 192칸·보수 22·최대 15.53mm).

2·3이 끝나기 전까지 이 스펙의 화면은 지금 엔진 산출물을 그대로 보여 준다: 밝은 PNG(편차맵·높이 그림·구배 지도), 1m 판정 셀, 10cm 편차맵. 캔버스 아트보드 중 2·3 의 몫(편차맵을 캔버스로 그리는 것, 해상도·판정 셀 선택 줄, 0.5m 수치)은 이 스펙에서 구현하지 않는다(§2).

## 2. 시각 정본과 우선순위

- 캔버스 "C안 전체 화면" 페이지의 17화면이 정본이다. 아트보드 원본은 `docs/design/dark/`에 커밋한다(`.dc.html`과 아트보드가 부르는 자산). 지난 리디자인과 같이 **아트보드와 계획 브리프의 코드가 어긋나면 아트보드가 이긴다.**
- 예외(2·3번 스펙 몫이라 이 스펙에서 무시한다): `ScanDone`의 판정 셀 선택 줄과 크기별 수치, `ScanDeviation`의 캔버스 렌더·표시 해상도 줄·범례, `Stage`(3D 탭)·`ScanDeviation`의 0.5m 수치. 이 화면들은 지금 산출물(1m 판정, 편차맵 PNG)로 같은 배치를 채운다.
- 아트보드의 예시 자료는 두 갈래다. 스캔 결과 화면(08~11)은 운영 현장 Test 의 실제 분석값, 나머지는 지난 Cloudscape 아트보드의 예시 현장 "세종 M2블록 아파트"다. 구현은 실제 데이터를 쓰므로 예시 값은 배치 참고일 뿐이다.

- **등급 색(화면용):** 적합 `#38d454` · 경계 `#fad647` · 보수 `#ff8c1f` · 재시공 `#ff332e` · 판정 불가 `#85817a`. 히트맵·구배 캔버스와 범례·배지가 모두 이 값을 쓴다. 지금 화면 캔버스가 쓰는 엔진 hex(`GRADE_COLOR`, `SLOPE_GRADE_COLOR`)는 화면에서 빠지고, PDF·엔진 PNG 만 엔진 hex 를 계속 쓴다. 색 계열이 같아 뜻은 어긋나지 않는다(사용자 확인).
- **상태 색:** 완료 `#38d454` · 진행 중 `#f2efe9` 속 빈 고리 · 대기 `#9a9690` · 경고 `#e0b341` · 오류 `#e05a4e` · 중지 `#85817a`. 파랑·청록 강조색은 쓰지 않는다(디자인 시스템 규칙). 예외는 구배의 배수구 표시 `#6fcdeb` 하나(데이터 색).
- **글꼴(next/font/google):** 본문 Montserrat + Noto Sans KR(한글), 제목 Noto Sans KR 우선, 라벨·숫자·파일명·시각 IBM Plex Mono, 큰 KPI 숫자만 Anton. Open Sans·Geist Mono 는 뺀다.
- **모양:** 버튼·입력칸 반지름 6px, 카드·스테이지 12px, 알약 999px. 버튼·입력칸·탭·메뉴 링크 높이 최소 44px. 그림자·그라데이션 채움 없음. `--shadow-cs-container`는 지운다.
- **도면 격자:** 본문(main) 배경에 1px 선 `rgba(242, 239, 233, 0.07)`, 가로 4칸·세로 3칸(아트보드 `motif` 기본값). 데이터 스테이지 안에는 깔지 않는다.
- **테마 분기 없음:** `prefers-color-scheme` 분기를 넣지 않는다. 앱은 어두운 팔레트 하나다. `globals.css`의 "다크모드 규칙을 다시 넣지 않는다" 주석의 사고(unlayered 규칙이 Tailwind 레이어를 이겨 판독 불가)는 이 결정으로 원천 차단된다. 밝은 모드 전환은 만들지 않는다.
- **포커스:** 키보드 포커스는 `outline: 2px solid ink; outline-offset: 2px`. 마우스 클릭에는 보이지 않게(`:focus-visible`).
- `__tests__/palette-sweep.test.ts`는 새 표를 기준으로 바꾼다: `cs-` 토큰과 옛 hex 재유입 금지, 화면 코드의 엔진 등급 hex 금지.

## 4. 화면 구조

### 4.1 워크플로우 (사용자 확인)

1. 진입 페이지에서 현장을 검색해 들어가거나 "새 현장"으로 그 자리에서 만든다 → 현장 대시보드.
2. 측정위치 탭에서 동·층·호·위치를 등록한다(업로드할 때 그 자리에서 만들어도 된다).
3. 현장에서 스캔(앱 밖).
4. 헤더의 "스캔 업로드" 또는 측정위치 줄의 버튼 → 측정위치·표면·기준을 고르고 파일을 올린다.
5. 사전 검사(자동) → 단위 확인(높이 그림을 보고 m·cm·mm 확정) → 평활도 분석 자동 시작(지금 동작: `unit-confirm-form.tsx`가 확정 직후 `analyze` 잡을 건다).
6. 결과: 히트맵·정밀 편차맵·3D·현장 사진 탭, 종합의견 수정. 필요하면 구배 분석 추가.
7. 나눠 찍었으면 측정위치 줄의 "스캔 정합"에서 두 스캔을 합친다.
8. 결과 화면의 "이 위치의 보고서 생성" 또는 보고서 탭 → PDF 생성 → 발행·다운로드.
9. 대시보드에서 위치별 판정 현황과 할 일을 보고, 보수 후 재스캔하면 4번부터 반복한다.

### 4.2 경로

| 화면 | 경로 | 셸 |
|---|---|---|
| 로그인 | `/login` | 상표만 |
| 진입(현장 찾기·새 현장) | `/` | 진입 헤더 |
| 현장 대시보드 | `/sites/[id]` | 현장 헤더(대시보드) |
| 측정위치 | `/sites/[id]/locations` | 현장 헤더(측정위치) |
| 보고서 목록 | `/sites/[id]/reports` | 현장 헤더(보고서) |
| 스캔 업로드 | `/sites/[id]/upload` (`?location=` 선택) | 현장 헤더(측정위치) |
| 스캔 작업대 | `/scans/[id]` (그대로) | 현장 헤더(측정위치), 현장은 스캔 → 측정위치 → 현장으로 찾는다 |
| 정합 시작·정합 | `/registrations/new`, `/registrations/[id]` (그대로) | 현장 헤더(측정위치) |
| 보고서 생성·상세 | `/reports/new`, `/reports/[id]` (그대로) | 현장 헤더(보고서) |
| 설정 | `/settings` | 진입 헤더 |

옛 경로 처리:
- `/upload?location=X` → `/sites/{X의 현장}/upload?location=X`(영구 리다이렉트). `/upload`(위치 없음) → `/`.
- `/reports` → `/`. `/sites/new` → `/`(새 현장은 진입 페이지 안에서 만든다).
- `/analyses/[id]`, `/scans/[id]/confirm-unit`의 지금 리다이렉트는 그대로.
- 스캔·정합·보고서 상세 URL 을 그대로 두는 이유: 보고서·알림·사용자 북마크가 이미 그 주소를 가리킨다.

### 4.3 셸

- **진입 헤더**(`/`, `/settings`): FLATNESS 상표(`/` 링크) + 오른쪽 계정 메뉴 버튼.
- **현장 헤더**(현장 안 전부): FLATNESS 상표(`/` 링크, "현장 목록으로") / 현장 이름 버튼(누르면 현장 바꾸기 목록, 지금 현장 표시) / 현장 메뉴 "대시보드 · 측정위치 · 보고서"(활성 하나에 `aria-current="page"`와 2px 밑줄) / 오른쪽 "스캔 업로드" 주 버튼(`/sites/[id]/upload`) / 계정 메뉴 버튼.
- **계정 메뉴:** 이메일을 라벨로 한 버튼 → 펼침 목록 "설정", "로그아웃". 키보드(Enter/Space 열기, Esc 닫기, 화살표 이동)와 바깥 클릭 닫기.
- **현장 바꾸기 목록:** 현장 이름 검색칸 + 이름 목록(이름 순. `sites`에 최근 활동 시각이 없어 활동 순 정렬은 집계가 필요하므로 하지 않는다), 끝에 "모든 현장 보기"(`/`). 같은 키보드 규칙.
- 지금의 `ConsoleShell`·`TopNav`·`SideNav`는 지운다. `/login`만 상표 헤더.
- **브레드크럼:** 현장 안 화면은 "현장 / 현장 이름"으로 시작하지 않는다(현장은 헤더에 있다). 탭 이름부터: `측정위치 / 101동 · 3층 · 301호 · 거실 / 스캔 · 바닥 · 2026-09-03`. 측정위치 표기는 부분을 ` · `로 잇는다(구분자 `/`와 헷갈리지 않게). 탭 첫 화면(대시보드·측정위치·보고서 목록)에는 브레드크럼이 없다. 설정은 `현장 목록 / 설정`.

## 5. 화면별 요구

각 화면의 배치·문구는 아트보드가 정한다. 여기에는 경로·데이터·동작만 적는다.

| # | 아트보드 | 요구 |
|---|---|---|
| 01 | `Login` | 지금 로그인 동작 그대로. 카드 가운데, 진짜 `type=email`/`type=password` 입력 |
| 02 | `EntrySearch` | 지금 홈의 조회·집계(`buildSiteSummaries`, `countInProgress`)를 그대로 쓴다. 큰 검색칸이 현장 이름으로 목록을 거른다(클라이언트). 줄 전체가 `/sites/[id]` 링크. "새 현장"을 누르면 같은 화면에 입력 카드(현장명 필수·주소·메모, 지금 `new-site-form.tsx` 필드와 검증)가 펼쳐지고, 저장하면 새 현장의 대시보드로 간다. 검색 결과가 0건이면 안내 + "새 현장"(검색어를 현장명에 미리 넣는다) |
| 03 | `DashStatus` | 새 순수 함수 `buildSiteDashboard`(lib/domain, 단위 테스트)로 집계한다. KPI: 측정위치 수 · 스캔 수(삭제 제외) · 분석 완료(현재 평활도 분석 done) · 처리 중(queued·processing, 종류 무관) · 보고서 수(삭제 제외, 상태 무관). 판정 분포는 홈과 같은 3묶음(§9). **판정 현황 격자:** 동 → 층(`floor_order`) → 측정위치 타일. 타일 = 위치 이름 + 최근 현재 평활도 분석 판정 색(없으면 미분석 회색, 처리 중이면 고리) + 최근 스캔 날짜, 타일 전체가 그 위치의 최근 스캔(`/scans/[id]`) 링크, 스캔이 없으면 측정위치 탭의 그 줄(`/sites/[id]/locations#loc-<위치 id>`) 링크. **할 일:** 단위 확인 대기 스캔 → 실패(스캔·현재 분석) → 보고서 생성 실패 → 처리 중 순, 줄마다 "열기". 없으면 아트보드의 빈 문구. **최근 보고서:** 최근 5건 |

## 6. 공통 부품

`components/ui/`의 프리미티브를 새 토큰으로 다시 그린다. 이름과 쓰임은 그대로 두고 모양만 바꾸는 것이 원칙이다.

- **Button / LinkButton:** 주(ink 채움, ground 글자) · 보조(투명, line-3 테두리) · 위험(투명, `#e05a4e` 테두리·글자). 높이 44px.
- **Badge:** 테두리 태그(1px 색 테두리, 같은 색 글자, IBM Plex Mono 11px). 등급 배지는 등급 색, 중립은 line-3/ink-2, "외부 결과"는 점선 ink-2.
- **StatusIndicator:** 8px 점 + 글자. 진행 중은 속 빈 고리. `SCAN_STATUS_TYPE` 매핑은 그대로.
- **Alert:** 경고 `#e0b341`(role=status) · 오류 `#e05a4e`(role=alert) · 안내 line-3. 인라인 stroke SVG 아이콘.
- **TabBar:** 44px 알약 탭(활성 = ink 테두리 + surface-2 바탕 + 600).
- **Card(새):** surface 바탕 + line-2 테두리 + 12px.
- **KpiCard(새):** 눈썹 라벨 + Anton 40px 숫자 + 단위(IBM Plex Mono). 묶음은 `repeat(auto-fit, minmax(150px, 1fr))`.
- **Stage(새):** 검정 바탕 + line-2 테두리 + 12px + overflow hidden. 3D·히트맵·구배·편차맵·높이 그림·PDF 미리보기가 쓴다.
- **DataTable:** 표 상자는 surface + line-2, 가로로 넘치면 상자 안에서만 스크롤(`overflow-x: auto`), 머리는 IBM Plex Mono 11px dim, 숫자 열 오른쪽 정렬.
- **FormField:** 라벨 위, 입력칸 44px ground 바탕 line-3 테두리, 도움말 muted.
- **Breadcrumbs, PageHeader, KeyValuePairs, ProgressBar(바탕 line, 채움 ink), EmptyState, Spinner, VerdictBar:** 토큰만 바꾼다.
- **캔버스 그림:** `heatmap-view`, `slope-heatmap-view`, `overlay-view`, `point-picker`의 바탕·격자·글자·등급 색을 새 값으로. `points3d-view`는 이미 검정이고 둘레만 바뀐다.

## 7. 휴대폰 (390px)

- 페이지 전체 가로 스크롤이 생기면 안 된다(표만 상자 안에서 스크롤).
- 헤더는 줄바꿈된다: 상표·현장 이름 / 메뉴 / 업로드·계정. 메뉴 링크와 버튼은 44px 그대로.
- 도구 줄·버튼 묶음은 wrap, 나란한 카드는 아래로 쌓인다(`flex: 1 1 420px` 식), KPI 는 2열 격자.
- 검정 스테이지는 최소 높이 320px.
- 검증: 데스크톱 1440 과 휴대폰 390 두 폭에서 캡처한다(§11).

## 8. 접근성

- 대비: ink·ink-2·muted 는 ground·surface 위에서 4.5:1 이상. dim(`#85817a`)은 surface 위 4.5:1 경계라 11px 눈썹 라벨에만 쓴다.
- 진짜 `<button>`·`<a>`·`<input>`+`<label>`만 쓴다. 아이콘만 있는 버튼은 `aria-label`. 표는 `<th scope="col">`.
- 현장 바꾸기·계정 메뉴는 `aria-haspopup`·`aria-expanded`와 §4.3 키보드 규칙.
- 상태를 색만으로 말하지 않는다: 등급·상태는 늘 글자(또는 숫자)를 함께 둔다.

## 9. 문구·용어

- 판정 분포 3묶음의 이름을 고친다: 지금 "적합 · 주의 · 재시공"은 세 번째 묶음에 보수가 들어 있는데 "재시공"이라 부르고, 두 번째 묶음은 등급 이름("경계")과 다르다. 새 이름 **"적합 · 경계 · 보수·재시공"**(묶음 규칙 `toBarCounts`는 그대로).
- 화면에 보이는 글자에 em dash(—)를 쓰지 않는다(저장소 규칙).
- `<title>`은 "Flatness · 화면 이름"으로 바꾼다(지금 "Flatness — 평활도 분석 콘솔"은 em dash 가 있고, 콘솔이라는 옛 이름이다).

## 10. 바뀌지 않는 것

DB 스키마·RLS·마이그레이션, 워커, 엔진, PDF 보고서, 스캔·정합·보고서 상세 URL, 3D 뷰어 로직, "브라우저는 등급을 계산하지 않는다"(리트머스 테스트), 지금의 데이터 조회·집계 규칙(kind 필터, 처리 중 집계 등). 새 집계 `buildSiteDashboard`도 등급을 계산하지 않고 엔진이 낸 `overall_verdict`만 센다.

## 11. 테스트와 검증

- **단위 테스트:** 팔레트 스윕(새 표 기준), 셸(활성 메뉴, 현장 바꾸기·계정 메뉴 키보드), 경로·리다이렉트, `buildSiteDashboard`(빈 현장, 처리 중, 실패, 판정 불가, 여러 동·층 정렬), 업로드 폼의 현장 고정, 보고서 목록의 현장 범위 조회. 클래스 이름이 바뀌어 깨지는 지금 테스트는 의미를 지키며 고친다(대상을 지우지 않는다).
- **빌드:** `tsc` 0, `next build` 통과, vitest 전부 통과.
- **화면 대조:** 17화면을 1440·390 에서 캡처해 아트보드와 나란히 비교한다. 데이터 화면은 사용자가 로그인한 세션에서 확인한다(비밀번호는 사용자가 직접 입력한다). 로그인 없이 볼 수 있는 부분은 지난번처럼 jsdom 렌더 + 컴파일된 CSS 정적 서버로 먼저 대조한다.
- **배포:** 대시보드만 바뀌므로 마이그레이션 없음. main 푸시는 사용자 지시가 있을 때만.

## 13. 후속 과제 (이 스펙 밖)

- 2번 스펙: 엔진 화면용 그림, 편차맵 클라이언트 렌더·해상도. 이때 정밀 편차맵(침하 = 초록)과 3D 뷰어(평탄 = 초록, 침하 = 노랑)의 초록 뜻이 다른 문제도 정한다.
- 3번 스펙: 판정 셀 크기 선택(기본 0.5m), 보고서에 셀 크기 표기.
- 작은 스캔 처리: 0.15m² 판처럼 엔진 최소 구역(1m²)보다 작은 스캔, 점이 적을 때 3D 점 크기, 작은 판에 과한 과장 배율.
- 밝은 모드는 만들지 않는다.
